# smart-commit コミット後のフック書き換えへの対処（正本）

SKILL.md [7] コミットループ手順 5 のポインタから、記録したツリー ID と `git rev-parse HEAD^{tree}` の不一致、または新たな未ステージ差分・未追跡の出現を検出した場合にのみ読まれる。対処は本ファイルの規定に限る（作業ツリーには「HEAD + この単位」しか無いので、現れた差分はフック由来と断定できる）。

a と b の両方に該当する場合は a を先に判定し、a で取り消した場合は b を評価しない（a が続行なら続けて b を判定する）。a・b のいずれも中断しなかった場合は SKILL.md [7] 手順 6 へ進む。

a. index 書き換え（＝コミットに入った）: git rev-parse HEAD^{tree} が記録した
   ツリー ID と不一致なら、フックが index を書き換えてからコミットされている
   （lint-staged 等）。差分が当該単位のファイル内に収まっていれば、ディスク内容へ
   軽量検証を再実行し、OK なら続行して報告に記録、NG なら git reset --soft
   HEAD~1 でコミットを取り消して中断・報告（検証を通らない変更を履歴に残さない）。
   プラン外のファイルに及んでいれば同じく取り消して中断・報告。
b. 作業ツリー書き換え（＝コミットに入っていない）: 新たな未ステージ差分・未追跡が
   現れた場合。当該単位のファイル内なら、まずディスク内容へ軽量検証を再実行し、
   OK ならフック差分の出た当該単位のファイルを `git add -- <path>` でステージし、`git write-tree` で
   ツリー ID を記録し直してから git commit --amend --no-edit で 1 回だけ取り込んで報告に記録する
   （amend 後の `git rev-parse HEAD^{tree}` がこの記録し直した ID と不一致、または新たな差分が
   現れても取り込まず、フック差分を未コミットのまま残して中断・報告）。NG なら
   amend しない（コミットは検証済み内容のまま）。フック差分を未コミットのまま
   残して中断・報告。プラン外のファイルなら amend せず中断・報告。
