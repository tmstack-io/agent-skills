# hermes TUI 起用 — 固有差分

hermes（Hermes Agent）をペインで起用するときのハーネス固有差分。共通手順の正本は [../SKILL.md](../SKILL.md)（ペイン操作は `mux.sh` 経由）。

## 起動

`mux.sh run` に渡す起動コマンド:

```sh
hermes --tui -m '<モデル>' --provider '<プロバイダ>' --in '<プロジェクトルート>'
```

- **モデル指定は必須**（hermes は特定モデルと結びつかないオープンハーネスであり、既定モデルに任せる起用経路を持たない — ../SKILL.md カタログ節）。カタログの指定値 `<プロバイダ>:<モデル>` を**最初のコロンで分割**し、プロバイダ部を `--provider`、モデル部を `-m` に渡す。
- **`-m` に `<プロバイダ>:<モデル>` を丸ごと渡さない**: `--tui` は `-m` の値をプロバイダ解決せずそのまま推論 API のモデル名として送るため、`-m custom:fugu` は `HTTP 404: Model "custom:fugu" not found` で全応答が失敗する（0.20.5 実測）。
- **reasoning effort は TUI 起用では指定できない**: `--reasoning` は `--tui` では黙って無視される（0.20.5 実測。`--reasoning medium` 付き起動でもフッターは `high` のまま。TUI 起動経路 `_launch_tui` が reasoning を受け取らないことをソースでも確認）。実効 effort は hermes の設定 `agent.reasoning_effort` 由来であり、起動後のフッター表示で確認する（実測環境では `high` 表示だった）。`@<エフォート>` 付き指定は `catalog.sh validate` が拒否する。
- cwd は `--in` で固定する。
- **`--cli`（従来型の REPL）でも起用できる**: `hermes --cli -m '<モデル>' --provider '<プロバイダ>' --in '<プロジェクトルート>'`（0.23.1 実測）。`--cli` は通常の画面で描くため、画面の履歴を含めて読める。`--tui` は代替画面で描く。長い返答を画面から読む直送委譲には `--cli` が向く。

## trust ダイアログ

なし（0.20.5 実測。プロジェクトルート指定の起動で trust / 初期ダイアログは表示されず、直接入力待ちに達した）。

## エージェント検知と受理判定

- エージェント名 `hermes`。**`agent_session` は報告されない**（実測）— 受理完了の判定に `agent_session` は使わず、working 遷移＋（未遷移時は）../SKILL.md の「タスクの委譲」手順3の二分で判定する。
- 起動直後の `agent_not_found` レース（../SKILL.md「ペインの起動」の起動シーケンスに含まれる再実行で対処）は hermes でも実測した事象である。

## 権限モデル

0.23.1 での実測（承認の仕組みと承認ダイアログ）は下記「承認ダイアログ」が持つ。0.20.5 の既定設定では、cwd 内のファイル読み取り・**cwd 外（成果物置き場）へのファイル書き込み**・シェル実行（通信規約の push を含む）がいずれも**無確認で実行される**（0.20.5 実測）。承認機構自体は存在する（危険コマンド承認プロンプト。`--yolo` はその全バイパス）が、今回の委譲では承認ダイアログ・blocked 遷移は発生しなかった（下記「未検証」）。`--yolo` は使わない（防御の正本は ../SKILL.md「呼び出しパラメータ」の裁定スコープ項）。

## 承認ダイアログ

0.23.1 実測（Rex バックエンド）。

- **承認の仕組み**: 危険なコマンドの規則（権限を全員書き込み可にする `chmod`、`find … -delete` 等）に一致したシェル実行が承認の対象になる。既定の設定（`approvals.mode` が `smart`）では、補助の LLM が対象のコマンドを先に判定し、安全と判定したものは**ダイアログを出さずに実行する**。したがって、同じコマンドでもダイアログが出る回と出ない回がある。コマンドが承認の対象かどうかは、`hermes approvals test -- <コマンド>` で実行せずに判定できる（終了コード 0 = 対象外、2 = 承認の対象、3 = 拒否）。
- **状態の申告は無い**: 承認待ちは blocked として報告されない。画面を読んで見分ける。
- **`--tui` のダイアログ**: 見出しは `⚠ approval required · <規則名>`。選択肢は2形ある — 3択（`1` Allow once ／ `2` Deny ／ `3` No, and tell Hermes what to do instead。補助の LLM が拒否と判定したとき）と、5択（`1` Allow once ／ `2` Allow this session ／ `3` Always allow ／ `4` Deny ／ `5` No, and tell Hermes what to do instead。判定を保留したとき）。**Deny の番号が形によって違う**ため、番号を固定で送らず、画面の選択肢を読んで選ぶ。数字キーは Enter なしで確定するので、`mux.sh answer` ではなく `mux.sh key <ペインID> <番号>` で送る（`answer` の Enter は、ダイアログが閉じたあとの入力欄へ届く）。
- **`--tui` では画面静止による検知が成立しない**: ダイアログの表示中も、ステータス行の表示（顔文字と動詞）が約3秒ごとに切り替わる。画面静止推定で状態を読むバックエンドでは pull 安全網が発火しないため、`mux.sh wait-output <ペインID> "approval required" <タイムアウトms>` を安全網と並べて待つ。ダイアログは既定で 300 秒後に時間切れになる。
- **`--cli` のダイアログ**: 見出しは `Dangerous Command`。選択肢は `1` Allow once ／ `2` Allow for this session ／ `3` Add to permanent allowlist ／ `4` Deny ／ `5` Show full command で、残り時間（300 秒）を表示する。`mux.sh answer <ペインID> "4"` で拒否、`"1"` で許可する。表示中の画面は静止するため、画面静止推定の安全網は発火する。
- **裁定**: 基準は ../SKILL.md「指揮者裁定」に従う。許可は `Allow once` だけを使い、セッション単位・恒久の許可（`Allow this session` / `Always allow` / `Add to permanent allowlist`）は選ばない。
- **ダイアログが出ていないときに番号を送らない**: 自動承認された回に送った番号は、プロンプトとして送信される（`--cli` で実測）。送る前に画面でダイアログの表示を確かめる。

## 固有の注意

- **`--tui` では本文をパスで終えない**: 送信本文がファイルのパスで終わると、入力欄の上にファイル名の補完候補の枠が出て、Enter が候補の確定に使われ、送信されない。このとき画面が変わるため `mux.sh submit` は終了コード 0 を返す（0.23.1 で2回再現。Enter をもう1回送ると送信される）。規定の文面「`<パス> を読んで実行せよ`」のように、パス以外で終える。
- **シェル実行の子プロセスへ、マルチプレクサの環境変数を渡さない**（0.23.1 実測、Rex バックエンド）: `REX_SESSION` / `REX_BLOCK` が子プロセスに無く、通信規約の push が `mux.sh detect` の失敗で終了コード 1 になる。Rex での対処は `../backends/rex.md` の (7) が持つ。herdr・cmux で同じことが起きるかは未検証である。
- **入力待ちの間もフッターの経過時間を更新し続ける**（0.23.1 実測。`--tui`・`--cli` とも）。画面静止推定で状態を読むバックエンドでは、数字を無視して比較する必要がある（Rex は対応済み）。

- ツール活動（`● Read File` / `● Write File` / `● Terminal`）と応答本文がペインに表示され、観戦できる。可視画面・`--scrollback` のどちらでも読み取れた（alt-screen 由来の不可視は観測されなかった）。
- ハーネス自身による push は無確認で実行され、確実に届く（実測: 1/1 到達）。pull 安全網は共通原則どおり併設する。
- 完了後は idle に戻る（今回の完了時は done を経ず idle で安全網が発火した。エラーで応答が打ち切られた場合に done を報告した観測もある）。`--until` 無しの安全網で受ける共通原則に従う。
- 起動時に自前の skills・toolsets・memory を注入する（起動画面に表示）。素の起動で起用し、干渉が観測されたら本書に追記する。

未検証: herdr・cmux バックエンドでの承認ダイアログの検知と、環境変数の引き継ぎ / `--cli` のダイアログでの許可（`"1"`）/ 同一ペインへの次の委譲での文脈保持。

改善候補: hermes の将来バージョンで `--tui` が `--reasoning` を受けるようになったら、`@<エフォート>` 対応（validate の許容値照合と起動コマンドへの付加）を追加する。
