# hermes TUI 起用 — 固有差分

hermes（Hermes Agent）をペインで起用するときのハーネス固有差分。共通手順の正本は [../SKILL.md](../SKILL.md)（ペイン操作は `mux.sh` 経由）。

## 起動

`mux.sh run` に渡す起動コマンド:

```sh
hermes --tui -m '<モデル>' --provider '<プロバイダ>' --in '<プロジェクトルート>'
```

- **モデル指定は必須**（hermes は特定モデルと結びつかないオープンハーネスであり、既定モデルに任せる起用経路を持たない — ../SKILL.md カタログ節）。カタログの指定値 `<プロバイダ>:<モデル>` を**最初のコロンで分割**し、プロバイダ部を `--provider`、モデル部を `-m` に渡す。
- **`-m` に `<プロバイダ>:<モデル>` を丸ごと渡さない**: `--tui` は `-m` の値をプロバイダ解決せずそのまま推論 API のモデル名として送るため、`-m custom:fugu` は `HTTP 404: Model "custom:fugu" not found` で全応答が失敗する（0.20.5 実測）。
- **reasoning effort は TUI 起用では指定できない**: `--reasoning` は `--tui` では黙って無視される（0.20.5 実測。`--reasoning medium` 付き起動でもフッターは `high` のまま。TUI 起動経路 `_launch_tui` が reasoning を受け取らないことをソースでも確認）。実効 effort は hermes の設定 `agent.reasoning_effort` 由来であり、起動後のフッター表示で確認する（実測環境では `high` 表示だった）。`@<エフォート>` 付き指定は `catalog.sh validate` が拒否する。
- cwd は `--in` で固定する。

## trust ダイアログ

なし（0.20.5 実測。プロジェクトルート指定の起動で trust / 初期ダイアログは表示されず、直接入力待ちに達した）。

## エージェント検知と受理判定

- エージェント名 `hermes`。**`agent_session` は報告されない**（実測）— 受理完了の判定に `agent_session` は使わず、working 遷移＋（未遷移時は）../SKILL.md の「タスクの委譲」手順3の二分で判定する。
- 起動直後の `agent_not_found` レース（../SKILL.md「ペインの起動」手順5の再実行で対処）は hermes でも実測した事象である。

## 権限モデル

既定設定では、cwd 内のファイル読み取り・**cwd 外（成果物置き場）へのファイル書き込み**・シェル実行（通信規約の push を含む）がいずれも**無確認で実行される**（0.20.5 実測）。承認機構自体は存在する（危険コマンド承認プロンプト。`--yolo` はその全バイパス）が、今回の委譲では承認ダイアログ・blocked 遷移は発生しなかった（下記「未検証」）。**書き込みの遮断はブリーフの規律が第一の防御**であり、`--yolo` は使わない。

## 固有の注意

- ツール活動（`● Read File` / `● Write File` / `● Terminal`）と応答本文がペインに表示され、観戦できる。可視画面・`--scrollback` のどちらでも読み取れた（alt-screen 由来の不可視は観測されなかった）。
- ハーネス自身による push は無確認で実行され、確実に届く（実測: 1/1 到達）。pull 安全網は共通原則どおり併設する。
- 完了後は idle に戻る（今回の完了時は done を経ず idle で安全網が発火した。エラーで応答が打ち切られた場合に done を報告した観測もある）。`--until` 無しの安全網で受ける共通原則に従う。
- 起動時に自前の skills・toolsets・memory を注入する（起動画面に表示）。素の起動で起用し、干渉が観測されたら本書に追記する。

## 検証記録

2026-08-27 実測（hermes 0.20.5 / herdr バックエンド / Claude Code 指揮者、スモーク委譲1件）: `--reasoning medium` 付き TUI 起動でフッターが `high` のままである事象（--reasoning の無視）/ `-m custom:fugu` 丸ごと指定の 404 失敗と `-m fugu --provider custom` 分割指定での正常起動 / trust・初期ダイアログなし / エージェント検知（`hermes`・idle/working/done を観測。`agent_session` は非報告）/ 起動直後の `agent_not_found` レースと数秒後の再実行での解消 / 委譲の受理（working 遷移）/ cwd 内読み取り・cwd 外（成果物置き場）書き込み・シェル実行（push）の無確認実行 / push 到達（1/1）と回答ファイルの検収 / ブリーフ規律の遵守（git 操作なし・指定ファイル以外の書き込みなし）/ reasoning 既定 high のフッター表示（`fugu high`）。

未検証: 承認ダイアログの形式・blocked 遷移（今回の委譲では発生せず。遭遇したら ../SKILL.md「未知ダイアログの遭遇プロトコル」で処理し本書へ追記する）/ 同一ペインへの追送によるラウンド間文脈保持。

改善候補: hermes の将来バージョンで `--tui` が `--reasoning` を受けるようになったら、`@<エフォート>` 対応（validate の許容値照合と起動コマンドへの付加）を追加する。
