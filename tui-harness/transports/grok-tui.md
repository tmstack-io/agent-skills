# grok TUI 起用 — 固有差分

grok をペインで起用するときのハーネス固有差分。共通手順の正本は [../SKILL.md](../SKILL.md)（ペイン操作は `mux.sh` 経由）。

## 起動

`mux.sh run` に渡す起動コマンド:

```sh
grok --cwd '<プロジェクトルート>'
```

- ../SKILL.md「委譲先の確定と検証」で確定したモデルを `-m <モデル>` で必ず付加する（実効モデルは入力欄フッターに表示される）。

## trust ダイアログ

未 trust のディレクトリでは codex と同型の trust ダイアログが表示される（0.2.114 実測。cwd 単位）。`mux.sh wait-output <ペインID> "Do you trust" 15000` で確定待ちし、マッチしたら `mux.sh key <ペインID> y` の**単キー送信**（Enter 不要）で通過する（タイムアウト＝ダイアログなし・trust 済みは正常分岐）。

## エージェント検知と受理判定

- エージェント名 `grok`。**`agent_session` は null のことがある**（実測）— 受理完了の判定に `agent_session` は使わず、working 遷移＋（未遷移時は）../SKILL.md の「タスクの委譲」手順3の二分で判定する。
- 起動直後の `agent_not_found` レース（../SKILL.md「ペインの起動」の起動シーケンスに含まれる再実行で対処）は grok で実測した事象である。

## 権限モデル

権限は**選択的承認モデル**である（0.2.114 実測）。読み取り系のシェル実行・ファイルの読み書き・通信規約の push は無確認で実行されるが、**書き込み効果のあるシェルコマンド（`mkdir` 等）は承認ダイアログ（`1 always-approve ／ 2 Yes, proceed ／ 3 No, reject`）を出し、エージェント状態が `blocked` になる**（ペインタイトルに「⚠ Action Required」）。裁定は ../SKILL.md の「指揮者裁定」に従う: `mux.sh read`（--scrollback）で内容を確認し、妥当なら「今回のみ許可」の番号を `mux.sh answer` で送って通過し、安全網を張り直す。**選択肢の番号は版によって違うため、送る前に画面で確かめる**: 0.2.114 は上記の3択で「今回のみ許可」は `2`、1.0.77 はシェルが5択（`1` always-approve ／ `2` Always allow: <コマンド> ／ `3` Yes, proceed ／ `4` No, reject ／ `5` Never allow）、ファイル編集が4択（`1` always-approve ／ `2` このセッションの編集をすべて許可 ／ `3` Yes ／ `4` No, reject）で、「今回のみ許可」は `3`、拒否は `4` である。`1`（always-approve）は書き込みスコープを別途制限できる場合に限り、恒久的な許可（1.0.77 の `2`）は選ばない。承認が出ない書き込みも多い（防御の正本は ../SKILL.md「呼び出しパラメータ」の裁定スコープ項）。

1.0.77 では、承認待ちが出る範囲が起動時の権限モードで変わる（実測）。上記の起動コマンドでは起動時のモードが `auto-review`（入力欄の枠に表示）になり、`mkdir` を含む書き込みで承認待ちが出なかった。`--permission-mode default` で起動すると、`chmod` とファイル編集ツールで承認待ちが出た（`mkdir`・リダイレクトでの書き込み・`rm -r`・`curl` は既定のモードでも無確認だった）。モードは Shift+Tab で切り替わる。

## 固有の注意

- **`mux.sh read` は `--scrollback` を必ず付ける**: grok は terminal alternate screen で描画するため、可視画面ソースでは応答本文が見えないことがある（実測）。受理判定の二分・応答の直接回収・ダイアログ確認はすべて `--scrollback` で行う。
- ツール活動（`◈ Read` / `◆ Creating ...`）と思考の経過（`◆ Thought for ...`）がペインに表示され、観戦できる。
- ハーネス自身による push は無確認で実行され、確実に届く（実測: 利用スキルからの委譲2件で計6/6到達。選択的承認モデルでも push はブロックされなかった）。pull 安全網は共通原則どおり併設する。

## 検証記録

2026-11-11 実測（指揮者 = Claude Code、Rex バックエンド、grok 1.0.77 / grok-4.7。各1回の試行）: 起動コマンドのままでは起動時のモードが `auto-review` になり、成果物置き場の中の `mkdir` で承認待ちが出ない / `--permission-mode default` での起動では、`chmod 600` で5択、ファイル編集ツールで4択の承認ダイアログが出て `blocked` になる（`3` で許可して続行、`4` で拒否してファイルは未変更）/ 同じ起動で `mkdir`・リダイレクトでの書き込み・`rm -r`・`curl`（作業ディレクトリの外への書き込みと削除を含む）は無確認で実行 / Shift+Tab は 既定 → plan → auto-review → always-approve の順に循環。`auto-review` になる原因は切り分けていない。

2026-10-14 実測（指揮者 = Claude Code、herdr 0.9.3 バックエンド、grok 1.0.52 / grok-4.7。直送上限の見直し）: 入力欄は枠線 `│` で囲まれ、右端にスクロールバー（`▃` `█` 等のブロック要素）が出る（`submit` の出現確認はこれらを読み飛ばす）。6,000・12,000・24,000 文字で `submit` が 3・10・31 秒。48,000 文字は取り込みに数十秒かかり、取り込み後に Enter に反応しなくなった（CPU 約 100% のまま）。取り込み中に送った次の貼り付けは捨てられる。送信本文の会話内エコーは先頭3行に畳まれる（詳細は `../direct.md` の実測記録）。

2026-09-15 実測（指揮者 = Claude Code、herdr バックエンド。`mux.sh submit` の導入検証、ADR 0015）: trust 済み cwd のダイアログなし起動 / `submit` 1 回で送信（送信エコー `❯` と返答 OK を `--scrollback` で回収）/ `close` の消滅確認。

2026-07-30 実測（検証＋利用スキルからの委譲1件・同一ペインへの追送を含む計3回の実運用）: trust ダイアログなしの起動（trust 済み cwd）/ エージェント検知（`grok`・status。`agent_session` は null）/ 読み取りの無確認実行 / ワークスペース内書き込みの無確認実行 / push の無確認実行と到達（3/3。書き込み規律・ブリーフ遵守も3回とも違反なし）/ 委譲の受理と同一ペインへの次の委譲での文脈保持 / モデル名のフッター表示（`Grok 4.5 (high)`）/ alt-screen 描画により可視ソースで応答が見えない事象と scrollback での回収。

2026-07-30 追試（同日中の別プロジェクト cwd での利用スキルからの委譲1件・同一ペインへの追送を含む計3回の実運用、grok 0.2.114）: trust ダイアログの表示確認（cwd 単位。`y` 単キーで通過。同日先行実測の「表示されない」は trust 済みディレクトリでの観測とみなす）/ 書き込み効果シェルでの承認ダイアログと blocked 遷移（安全網の発火で検知し `2`＋Enter で通過）/ 読み取り系シェル・ファイル書き込み・push の無確認実行（push 3/3 到達）/ 起動直後の `agent_not_found` レースと再実行での解消。
