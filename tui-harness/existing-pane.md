# tui-harness 既存ペインの起用（正本）

SKILL.md「既存ペインの起用」節のポインタから読まれる規定の正本（適用条件は SKILL.md 側が持つ）。cmux バックエンドでの読み替えは `backends/cmux.md` が持つ。

稼働中の既存ペインを委譲先として採用する。herdr のペイン操作はソケット API でタブ・ワークスペースを跨いで届くため、採用後の手順（「タスクの委譲」以降。受理判定・pull 安全網・応答の受け取り・指揮者裁定を含む）は新設ペインと同一である（タブ・ワークスペース跨ぎの send / key / read / wait-output / agent-wait は実測検証済み。指揮者: Claude Code）。

1. **解決**: `mux.sh self; mux.sh list && mux.sh tabs` を1回のシェル実行で取り（`;` 区切り — self が失敗しても list / tabs を同じ実行で得るため）、self の `pane_id` を**指揮者ペイン ID**（通信規約に記載する値）として対応表に記録し、self の `workspace_id` を**自ワークスペース**とする。self が非0終了した場合はSKILL.md「ペイン配置」手順1の非0分岐と同じく、同じ実行で得た list の一覧を添えて散文提示で自ペインの ID をユーザーに確認し、確認した ID を指揮者ペイン ID として記録して、その ID を持つペインの `workspace_id` を自ワークスペースとする。指定値を各ペインの `pane_id` / `tab_id` / `terminal_title_stripped`（部分一致可）、および `tabs` の `label`（ユーザーが付けたタブ名。部分一致可。一致したタブの `tab_id` を持つペインへ展開する — ペイン一覧はタブ名を持たないため、タブ名指定はこの突き合わせでのみ解決できる）と照合する。タブ名・タイトルの照合は**自ワークスペース内の一致を優先**し、自ワークスペース内でちょうど1件なら手順2へ進む。自ワークスペース内に0件のときのみ全ワークスペースへ広げる。**ワークスペース跨ぎの確認**: 自ワークスペース外のペインに一致した場合は、ちょうど1件でも黙って採用せず、一致したペインの所属（ワークスペース名・タブ名）を添えて散文提示で採用可否を確認する（タブ名・タイトルは複数ワークスペースで重複しうるため、自ワークスペースのつもりの指定が別ワークスペースへ解決される誤爆を防ぐ）。`pane_id` / `tab_id` の完全一致は一意 ID のためスコープ優先を適用せず、そのまま1件確定とする。0件・複数件・指定値なしの場合は、`agent` フィールドを持つペインの一覧（ペイン ID・CLI・ワークスペース名・タブ名・タイトル・cwd・`agent_status`）を散文提示して選んでもらう（明示指定が0件・複数件だった場合は、その照合結果も示す。同名タブが複数ワークスペースにありうるため、一覧はワークスペースを添えて提示する）。候補の所属ワークスペースは list の `workspace_id` を自ワークスペースと突き合わせて判定し、散文提示に添えるワークスペース名は list / tabs の出力に名前のフィールドがあればそれを使い、無ければ `workspace_id` をそのまま添える。
2. **起用ゲート**: 解決したペインが次のすべてを満たさなければ採用せず、満たさない条件を示して呼び出し側の失敗規律に従い中止する（別候補への差し替え・新設への縮退は、呼び出し側が明示した場合のみ）:
   - `agent` フィールドが存在し、値がカタログ（`catalog.sh`）掲載の CLI 名と一致する（通信規約の送達と承認ダイアログの裁定基準は当該 transports の実測が正本であり、カタログ外エージェントには裁定根拠が無い）。
   - `agent_status` が idle である（作業中ペインへの割り込みをしない）。
3. **CLI・モデル・系統**: CLI は `agent` フィールドの値で確定する。ハーネスは起動済みのため、モデル・エフォートの指定・変更はできない（SKILL.md「委譲先の確定と検証」は適用しない。モデル・エフォート付きの指定値と `--pane` の併用は解釈せず、散文提示で再指定を求める）。利用スキルがモデル系統を要する場合は、`model-family.md` の実行中の系統の規則を委譲先ペインに準用する — 単一系統 CLI は静的に確定し、複数系統 CLI はペインの画面・セッション情報から実効モデルを特定して `catalog.sh family` で系統を得る。特定できなければ散文提示でユーザーに確認する。
4. **採用の記録**: 対応表に記録する（**採用ペインである旨を含む** — クローズ判定で参照するため）。

採用ペインの規律:

- **専有**: 委譲の開始から回収までの間、当該ペインは指揮者が専有する。ユーザーの直接入力が挟まると受理判定・回収が壊れるため、採用を宣言する際にその旨を伝える。
- **既存文脈**: ペインが保持する既存の会話文脈は消去できず、委譲はその文脈の上に乗る。それを予備知識という価値とみなすか汚染リスクとみなすかの判断・明記義務は利用スキル側の規定に従う。
- **cwd**: ペインの cwd は変更しない（SKILL.md「ペインの起動」の cwd 固定規定は適用されない）。ブリーフ・回答/報告ファイルのパスは常に絶対パスで受け渡す。
- **クローズ対象外**: 採用ペインは指揮者の所有物ではないため、SKILL.md「クローズ」の3条件が揃っても閉じない。委譲の終了時は、pull 安全網の停止（停止できる環境のみ）と対応表からの除去だけを行う。
