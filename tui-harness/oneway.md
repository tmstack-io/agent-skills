# tui-harness 片道委譲（正本）

SKILL.md「片道委譲」節のポインタから読まれる縮約形の正本（適用条件は SKILL.md 側が持つ）。

縮約形: ペインへブリーフを送って受理を確認した時点で委譲を完了とし、以後のペインの対話はユーザーに引き渡す（指揮者は回答を回収も観測もしない）。

- **適用する手順**: 「ペイン配置」「ペインの起動」「タスクの委譲」の手順1〜3（ブリーフの作成・送信・受理確認と再送）。ただし「タスクの委譲」手順1の回答/報告ファイルの絶対パスは記載せず（回答は置かれない）（対応表の見出しは SKILL.md の対応表の定義どおり CLI 名）。SKILL.md「委譲先の確定と検証」は適用し、異系統委譲（`model-family.md`）は利用スキルの要求に従う。
- **適用しない手順**: 通信規約ブロックのコピー（回収先が無い）、「タスクの委譲」手順4の pull 安全網、「応答の受け取り」、「指揮者裁定」、「クローズ」の3条件（ペインの主はユーザーになり、閉じる判断もユーザーが行う）。
- **呼び出しパラメータ**: 3値のうち**成果物置き場のみ**を定める（ブリーフの置き場。回答は置かれない）。push ラベルと裁定スコープは定めない。失敗規律（受理の再送上限超過時の終え方）は往復委譲と同じく利用スキルが定め、単発利用では SKILL.md「呼び出しパラメータ」末尾の既定を使う。
- **承認ダイアログ**: 受理確認後にペインで発生する承認ダイアログは、ユーザー自身がそのペインで応答する（指揮者は裁定しない。裁定スコープを持たないため）。
- **ペイン ID の伝達**: 受理確認後、利用スキル（単発利用では指揮者）はペイン ID と起動した CLI・モデルをユーザーに報告する（ユーザーがそのペインで続きを行うため）。「ペイン ID の揮発性」の規定はそのまま適用する（対応表に残す場合は増減操作のたびに `mux.sh list` で取り直す）。
- **既存ペインの起用との併用**: 利用スキルが既存ペインの起用を明示した場合、または `--pane` と `--oneway` を併用した場合は、「ペイン配置」「ペインの起動」の代わりに `existing-pane.md` の手順1〜3を適用する。採用ペインの専有は受理確認の時点で終わり（以後の対話はユーザーに引き渡す）、ペイン ID の伝達は採用ペインでも行う。
