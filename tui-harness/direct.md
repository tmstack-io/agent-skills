# tui-harness 直送委譲（正本）

SKILL.md「直送委譲」節のポインタから読まれる規定の正本（利用スキルが直送委譲を明示したときに適用する。加えて、cmux バックエンドでは直送委譲を適用せず、利用スキルはペインを立てる前に「直送委譲は cmux で未実測」と示して中止する — `backends/cmux.md` に直送委譲の読み替えは無い）。

往復委譲との差分だけを定める。初回はブリーフで文脈を渡し、2通目以降の指揮者の追問は**直送上限**以内ならペインへ直接送り、返答はペイン画面から読む。回収まで行う点は往復委譲と同じで、ペイロードは直送上限を超えるときだけファイルを通す。委譲先ペインは指揮者が専有し、専有中はユーザーがそのペインへ入力しない（採用ペインの専有規律と同じ）。

## 呼び出しパラメータ

往復委譲の3値（成果物置き場・push ラベル・裁定スコープ）に加えて、利用スキルは**直送上限**（1メッセージの上限文字数。改行を除いて数える）を定める。上限の既定値と指定手段は利用スキル側が持つ。

## 初回の委譲（ブリーフ）

「ペイン配置」「ペインの起動」（`--pane` なら `existing-pane.md`）、「タスクの委譲」手順1〜3 を適用する。ただし手順1の**回答/報告ファイルの絶対パス**は単一のパスとして記載せず、直送通信規約中の `<成果物置き場>/report-<n>.md`（委譲先が採番）がこれに代わる。また手順1のブリーフ末尾には往復委譲の通信規約ブロックの代わりに、次の**直送通信規約**を一字一句そのままコピーし、`<>` 内を実値に置換する（`<直送上限>` は呼び出しパラメータの値。`<n>` は委譲先が回答ごとに採番する枠としてそのまま残す）:

   BEGIN-直送通信規約（ブリーフ末尾へコピー）
   - 以後の追問は、このペインへ直接届くか、ファイルの絶対パスを添えた一行で届く（後者はそのファイルを読んでから答える）。
   - 回答はこのペインに書く。質問もこのペインに書く（別の通知手段は使わない）。
   - 回答が <直送上限> 文字（改行を除く。厳密に数えなくてよく、概算で超えそうなら超えるとみなす）を超えるときだけ、回答の全文を `<成果物置き場>/report-<n>.md`（n は 1 から順に採番）に書き、ペインには次の一行だけを書いてから、次を実行する:
     `<mux.sh> send <指揮者ペインID> "[<push ラベル>] done <回答ファイルの絶対パス>"` に続けて `<mux.sh> key <指揮者ペインID> Enter`
   - 上記コマンドが失敗した場合（Operation not permitted 等）: 回答ファイルはそのままに、同じ一行（`[<push ラベル>] done <回答ファイルの絶対パス>`）をペインに書いて終了する
   - 書き込みは <成果物置き場> の配下のみ。それ以外のファイルは作成・編集しない。
   - git のコミット・stash・ブランチ作成はしない。変更は作業ツリーに残す。
   END-直送通信規約

受理完了（手順2の条件）を確認したら、後述「返答の受け取り」で初回の返答を回収する（初回の返答も直送通信規約に従うため、往復委譲の「応答の受け取り」ではなく本書の手順を使う）。

## 追送（2通目以降）

1. **送信長の判定**: 送る本文の文字数（改行を除く）が直送上限以内なら直送する。超えるときは本文を `<成果物置き場>/note-<n>.md`（n は 1 から順に採番。既存と衝突すれば次の番号）に書き、ペインへ送る本文は `<note の絶対パス> を読んで答えよ` の一行に置き換える（直送通信規約の1項目目がこの形を委譲先に予告している）。黙って切り詰めない。
2. **送信と受理**: 「タスクの委譲」手順2 と同じ形で1回のシェル実行に束ねる。テキストは複数行でよい（改行は入力欄に改行として入り、送信は起こらない。実測は末尾）:

   ```sh
   <mux.sh> send "$PANE" "<本文>" \
     && sleep 1 && <mux.sh> key "$PANE" Enter \
     && <mux.sh> agent-wait "$PANE" --until working 15000
   ```

   受理完了の条件と、受理にならなかったときの二分（Enter 再送 / やり直し）・再送上限（合計2回）は「タスクの委譲」手順2〜3 と同じ。上限を超えたら呼び出し側の失敗規律に従う。
3. 受理完了ごとに「ペイン ID の揮発性」に従い、送信の直前に `mux.sh list` で ID を取り直す（往復委譲と同じ）。

完了条件: 送信した本文が受理完了し、直送上限を超えた本文は note ファイルに残っている。

## 返答の受け取り

受理完了のたびに、pull 安全網 `<mux.sh> agent-wait "$PANE" 1800000`（`--until` 無し）を**前面の同期実行**で待つ（直送委譲は会話のため、待っている間に指揮者が進める作業が無い。バックグラウンド実行は使わない）。発火したら `mux.sh read "$PANE" --scrollback --lines <L>` で画面を読み、三分類する（`<L>` の初期値は 200 と、`mux.sh list` の当該ペインの `scroll.viewport_rows` の 2 倍との大きい方）:

- **承認ダイアログで停止（blocked）** → 「指揮者裁定」に従い裁定する。許可なら送信して同じ安全網を張り直して待ち、拒否なら呼び出し側の失敗規律へ進む。
- **idle / done** → 次の順で返答を確定する:
  1. 指揮者ペインに `[<push ラベル>] done <パス>` の push が届いている、またはペイン画面の最後の非空行から 5 行以内にその一行がある → 回答ファイルを読む（読まずに次へ進まない）。回答ファイルが存在しない、または空なら 2 へ進む。
  2. 上記以外 → 画面テキストから**直前に送った本文の先頭行のエコー**を探す（note 経由なら `を読んで答えよ` の一行）。見つからなければ `--lines` を 2 倍にして読み直し、800 行まで広げても見つからなければ回収失敗として呼び出し側の失敗規律に従う。委譲先が直送上限の概算を外して長い返答をペインに書いた場合も、ここで画面から回収する（規約違反として失敗にしない）。
  3. エコーより後ろのテキストから、ハーネスの入力欄・ステータス行・空行を除いたものを返答とする（当該 transports に「直送委譲」節があれば、その画面マーカー — 送信エコー・返答の行頭記号 — で切り出す。無いハーネスでは指揮者が画面テキストを読んで返答部分を判別し、判別できなければ回収失敗として失敗規律に従う。黙って空の返答にしない）。
- **まだ作業中（working）** → 安全網を張り直して待機を延長する。延長は1回まで。2回目の発火は散文提示でユーザーに確認する（利用スキルがこの確認に代わる規定を持つ場合はそれに従う）。

完了条件: 送信した本文ごとに、返答（画面から切り出した本文、または回答ファイルの内容）を読み終えている。

## 適用しない手順

往復委譲の「応答の受け取り」（`question:` push の処理を含む。直送委譲では委譲先の質問は返答として画面に現れる）、往復委譲の通信規約ブロックのコピー（直送通信規約で置き換える）、「タスクの委譲」手順4（pull 安全網のバックグラウンド起動。直送委譲では「返答の受け取り」の前面同期実行が代わる）。「指揮者裁定」「未知ダイアログの遭遇プロトコル」「ペイン ID の揮発性」「クローズ」（3条件と採用ペインの除外）はそのまま適用する。
