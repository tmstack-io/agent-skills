# maestro ペイン経路

奏者経路がペイン経路（サブエージェント機構が無い環境）になった場合にのみ読む、ペイン経路固有の規定の正本。SKILL.md の「散文提示」「サブエージェント返却規約」等の定義を引き継いだ同一コンテキストで適用する。

## 採用条件（すべて満たした場合のみ採用する）

指揮者と同系統の CLI（codex 指揮者なら codex、grok 指揮者なら grok）を TUI マルチプレクサのペインで奏者に立てる。

1. tui-harness の SKILL.md を Read できる。解決順: `../tui-harness/SKILL.md` → 実行ハーネス自身のスキルディレクトリをプロジェクト側 → グローバル側の順（Claude Code: `.claude/skills/` → `~/.claude/skills/`、Codex: `.agents/skills/` → `~/.agents/skills/`。他ハーネス用のディレクトリは探さない）。見つからなければ復旧手順（`npx skills add tmstack-io/agent-skills --skill tui-harness`）を案内して起動を中止する。
2. tui-harness の `mux.sh detect` が検証済みバックエンドを返す。返さなければ「対応する TUI マルチプレクサが無いため maestro を起動できない」と警告を提示して終了する。
3. 指揮者の CLI の `transports/<CLI名>-tui.md` が存在する。無ければ tui-harness のカタログ外 CLI の追加手順を案内して起動を中止する。
4. **ユーザーの許諾**: 「サブエージェント機構が無いため、指揮者と同じ CLI（<CLI名>）をペイン分割で奏者に立てる。委譲は直列実行になる」ことを散文提示で明示し、許諾を得る。許諾が得られなければ起動を中止する。

## 運用

ペイン経路の運用は tui-harness の規定に従う。呼び出しパラメータ:

- 成果物置き場＝プロジェクト直下の `.maestro/`（ブリーフ・報告ファイル。git リポジトリで ignore されていなければ初回作成時に `.git/info/exclude` への追記を提案する。モード解除時は、削除対象のパスと中身を示して散文提示で削除可否を確認し、承認を得た場合のみディレクトリごと削除する。承認が得られなければ残置し、削除に失敗した場合はパスを添えて報告する）
- push ラベル＝`maestro-<タスク連番>`
- 裁定スコープ＝編集タスクはブリーフの対象ファイル＋成果物置き場、調査タスクは成果物置き場のみ（いずれも＋通信規約の push）
- クローズ期限＝モード解除時（解除時に tui-harness のクローズ手順の条件を満たしたペインから閉じる）

奏者ペインは役割（実装 / レビュー / 調査）ごとに使い回し、並列起動はしない（採用条件4の許諾どおり委譲は直列実行。SKILL.md「並列と進捗」の並列規定はサブエージェント経路にのみ適用する）。品質ゲートのレビュー奏者は、実装奏者と別のペインに立てる。

## 委譲の受け渡し

起動時に確定したロール別の実効モデル・エフォートを tui-harness の委譲手順の明示指定値として渡し、モデル・エフォートの照合と検証は同手順に委ねる（照合・検証に失敗した場合は散文提示で再確定した値を渡し直す。tui-harness 側で改めてモデル選択の散文提示はさせない）。ブリーフはファイルで渡す（tui-harness の「タスクの委譲」の書式に従う）。
