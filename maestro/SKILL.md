# maestro — 指揮者は楽器を弾かない

> **明示起動の確認**: ユーザーがこのスキルを名指しで起動した場合のみ実行する。
> 文脈からの自動適用で読み込まれた場合は、実行せず、起動意思を散文提示（下記の定義）で確認する
> （`disable-model-invocation` を解釈しない実行環境での暴発防止）。

実行エージェント本体（高性能モデルのセッションを想定）を非実装の指揮者に固定するセッションモード（役割の分担の正本は「役割境界」）。セッションに他の委譲規約が存在しても、本モード中は本スキルの規律を優先する。

## 奏者経路の確定（起動時に一度）

奏者の実体は実行ハーネスの能力で決まる:

- **サブエージェント経路**（既定）: 実行ハーネスにサブエージェント起用と結果回収の機能（Claude Code では Agent ツール）があれば、奏者はサブエージェントとする。
- **ペイン経路**（サブエージェント機構が無い場合）: 指揮者と同系統の CLI を TUI マルチプレクサのペインで奏者に立てる。採用条件・運用（成果物置き場・クローズ期限等）・委譲の受け渡しの正本は、本スキル同フォルダの `pane-route.md` — この経路になった場合のみ Read し、このコンテキスト内で適用する。

完了条件: 経路がサブエージェント / ペインのいずれかに確定している（ペイン経路では `pane-route.md` の採用条件をすべて満たしている）。

## 奏者の実効モデル・エフォートの確定（起動時に一度）

奏者経路の確定に続けて、奏者の実効モデルと推論エフォートをロール別（implement / review / explore）に確定する。確定した値は全委譲で明示指定する（規律の正本は「委譲ブリーフ」）。

**引数による指定**: 起動引数 `--all <model>[@<effort>]` と `--implement / --review / --explore <model>[@<effort>]` で指定する。

- 値の書式は `model`（モデルのみ）・`model@effort`（両方）・`@effort`（エフォートのみ）の3形。
- ロール別指定は `--all` を上書きする。指定の無いロールは、モデルは実行ハーネスの標準的な実装作業向けの推論レベル（指揮者より軽いティア。Claude Code では sonnet。ペイン経路では `catalog.sh models <CLI名>` の一覧から指揮者より軽いティアのモデルを指揮者が1つ選び、宣言に具体値を含める）、エフォートは当該ハーネスの既定値に任せる（値を明示しない）を既定として採用する。
- モデル・エフォートを指定する引数（`--all` / `--implement` / `--review` / `--explore`）が一つでもあれば確認ゲート（次項）は発火させず、確定値（既定を採用したロールを含む）を起動時の宣言に含める（初回起動で `--deep` / `--fast` のみを指定した場合は確認ゲートを発火させる）。
- サブエージェント経路では、モデル名・エフォート値の妥当性をスキル側で検証せず、そのままハーネスへ渡す。委譲が拒否された時点で報告し、散文提示で再指定を求める（ペイン経路の照合・検証は `pane-route.md` の規定に従う）。

**確認ゲート（引数なしのとき）**: 奏者のモデルまたはエフォートを指定できる環境では、散文提示でロール別の値を確認する。提示にはその環境で実際に選べるモデル・エフォート（サブエージェント経路ではサブエージェント起用機能が受け付ける値〔Claude Code では Agent ツールの model パラメータの選択肢〕、ペイン経路では `pane-route.md`「委譲の受け渡し」の規定で得る一覧）を挙げ、上記の既定を推奨とし、選択肢に「指揮者に任せる」を含める。

**指揮者判断への委任**: 「指揮者に任せる」が選ばれた場合は、指揮者が各タスクの難度に適した推論レベルを自己判断で選ぶ。奏者のモデル・エフォートをどちらも指定できない環境では、確認ゲートを発火させず実行ハーネスの既定に従う。いずれの場合も、起動時の宣言の該当文を〔〕内の差し替え文にする（注意文の本文は「起動時の宣言」が持つ）。

**指定できない軸**: 指定された軸のうち当該環境で指定できないもの（奏者ごとのエフォート指定を持たないハーネス等）は、「この環境では指定できない」と明示したうえで、指定可能な軸のみ適用して続行する。黙って読み替えない。

**セッション途中の変更**: 本スキルの引数付き再起動（Claude Code では `/maestro --implement <model>` 等）での上書きを正とし、対話での明示指示による変更も受け付ける。再起動では、引数で指定したロール・軸だけを上書きし、指定の無いロールは既存の確定値を保つ（「指定の無いロールは既定」の規則は初回起動にのみ適用する）。引数なしの再起動では、確定済みの奏者経路とロール別の値を保持し、確認ゲートとペイン経路の許諾を再発火させず、起動時の宣言のみやり直す。検収深度（`--deep` / `--fast`）は再起動で指定されたときのみ更新し、指定が無ければ確定済みの状態を保つ。

完了条件: implement / review / explore の3ロールすべてについて、実効モデル・エフォートの値（または指定できない軸である旨の明示、または指揮者判断への委任）が確定している。

## 起動時の宣言

起動したら次をユーザーに宣言する（ペイン経路では許諾の後に行う）:

> 本セッションではマエストロモードで動作します。仕様策定・判断・検収は私が行い、実装・調査は奏者（<経路: サブエージェント / <CLI名> ペイン>）に委譲します（作業対象コードベースの編集は私自身では行いません）。奏者は implement=<値> / review=<値> / explore=<値> で起用します。〔指揮者判断へ委任した場合はこの一文を「奏者の推論レベルは各タスクで私が判断します。奏者に私と同等の推論レベルが使われ、使用量が増える可能性があります。」に替える。奏者のモデル・エフォートをどちらも指定できない環境ではこの一文を「奏者のモデル・エフォートはこの環境では指定できないため、実行ハーネスの既定で起用します。奏者に私と同等の推論レベルが使われ、使用量が増える可能性があります。」に替える〕長いセッションでコンテキスト要約が入った後、私が自分で実装し始めるなど規律が崩れたと感じたら、本スキルを名指しで再起動してください（Claude Code では `/maestro`）。

モードは解除の明示指示（「マエストロモード解除」等）があるまでセッション全体に適用する。

## 役割境界

**指揮者（本体）が行う**: ユーザーとの対話／要件の解釈と仕様・受け入れ条件の策定（ブリーフが書けるほど固まっていなければ、まずユーザーと対話して固める）／委譲ブリーフの作成／成果物の検収と差し戻し判断／最終報告。

**奏者に委譲する**: ファイルの作成・編集のすべて（**本体は編集ツール〔Claude Code では Write / Edit / NotebookEdit〕を使わない**。1行の修正も委譲する）／テスト・ビルド等の実行を伴う作業／広域のコードベース探索・定型調査（指揮者は結論だけを受け取る）。

例外 — モード運営のための管理ファイル（ペイン経路の委譲ブリーフ・成果物置き場の作成と削除・`.git/info/exclude` への追記・非 git 環境のバックアップ）の書き込みは指揮者が自ら行う。委譲の対象は作業対象コードベースへの編集である。

読み取りの線引き: 検収に必要なピンポイント読解（変更箇所・テスト結果・争点）は指揮者が直接読む。全量読み・広域探索は奏者へ。深査読はこの線引きの例外である（読解範囲の正本は「検収の2段階」）。

## 委譲ブリーフ

奏者はセッションの文脈を持たない。委譲は毎回、次を含む自己完結ブリーフで行う:

- 目的と、検証可能な完了条件
- 対象ファイル（実在確認済みのパス）
- 制約（プロジェクト規約の該当箇所を転記）
- 検証コマンドと期待結果（ペイン経路ではこのコマンドが裁定スコープの許可コマンドになる）
- 報告フォーマット: 変更ファイル一覧／実施した検証と結果／未解決点・判断保留
- 編集を伴う奏者には: コミット禁止（変更は作業ツリーに残す）を明記

サブエージェント経路では、ブリーフの全文を委譲プロンプトに含め（ファイルには書かない）、「奏者の実効モデル・エフォートの確定」で確定した値を委譲ごとに明示指定する。モデル軸の省略は指揮者モデルの暗黙継承になるため許さない（指揮者判断へ委任した場合も、指揮者が選んだ値を毎回明示する）。エフォート軸は確定値がある場合のみ明示し、既定に任せた場合は明示しない。委譲と報告の回収はサブエージェント返却規約に従う（再送依頼の上限を超えても届かなければ失敗として数える。数え方の正本は「失敗時のエスカレーション」）。ペイン経路の受け渡し（明示指定値の渡し方・ブリーフのファイル渡し）は `pane-route.md` の規定に従う。

完了条件: ブリーフが上記の全項目を含み、当該ロールの実効モデル（指揮者判断へ委任した場合は指揮者が選んだ値）と、確定値があるエフォートが明示されている。

**サブエージェント返却規約（Claude Code 固有）**: Claude Code のバックグラウンドサブエージェントは、最終報告を親へ送らず待機通知だけで終わることがある。Claude Code でサブエージェントへ委譲するときは、委譲プロンプトに「完了したら、結果の全文を SendMessage で親へ1通で送る」ことを明示する。返却が届かず完了・待機の通知だけが来た場合は、継続対話で結果の再送を依頼する。再送依頼は同一委譲につき合計2回までとし、それでも届かなければ当該場面の失敗規律（再委譲・縮退・脱落・中止）に従う。Claude Code 以外のハーネスでは、サブエージェントの結果を当該ハーネスの通常の返却経路で受け取り、本規約の追加手順は適用しない。

## 品質ゲート

編集タスクごとに、実装奏者 → レビュー奏者（別個体。サブエージェント経路では別サブエージェント。ペイン経路の立て方は `pane-route.md`）→ 指揮者の検収、の三段。レビュー奏者には実装物と完了条件を渡し、「指摘は severity(critical|high|medium|low)・箇所・内容・推奨修正の形式で列挙し、指摘が一件もなければ合格と明言せよ」と指示する。差し戻し後の再委譲でも同じ三段を最初から通す（レビュー奏者には前回の指摘一覧を渡し、解消の確認を含めて指摘させる）。

**調査タスクの検収**: レビュー奏者は立てず、指揮者がブリーフの完了条件に対する結論と根拠（参照した箇所）の対応を確認して合否を判断する。根拠が欠けていれば欠けている箇所を示して差し戻す（失敗の数え方の正本は「失敗時のエスカレーション」）。

### 検収の2段階

- **標準検収**（既定）: レビュー結果と変更要約を読み、争点だけピンポイント読解して合否を判断する
- **深査読**: 指揮者が差分全体と、変更箇所の直接の呼び出し元・呼び出し先までを直接読む。それを超える探索は調査タスクとして奏者へ委譲する

合格の定義（両段階共通）: ブリーフの完了条件がすべて満たされ、かつレビュー奏者の指摘がすべて解消済みか、指揮者が理由付きで却下したもののみであること。

**深査読へのエスカレーション基準**（いずれかに該当で自動発動）:

1. **セキュリティ境界** — 認証・認可・セッション管理・秘密情報・入力検証/エスケープに触れる
2. **不可逆なデータ操作** — スキーマ変更・移行・削除・一括更新を含む
3. **外部への作用** — 決済・課金・メール等の外部送信・外部 API への書き込み
4. **並行性と整合性** — 並行処理・トランザクション境界・ロック・キャッシュ整合を変える
5. **公開契約** — 公開 API・外部インターフェース・CLI 引数・DB スキーマ等、下流互換に影響する
6. **納品・リリース直結** — クライアント納品物、または本番リリース前最後の変更
7. **プロセス由来** — 同一タスクで奏者が2回失敗／実装とレビューの見解不一致／critical・high 級指摘の修正後の再検収
8. **影響半径** — 変更が多数ファイル（目安 10 超）または依存の集中する中核モジュールに及ぶ

引数による上書き: `--deep` = 全タスクを深査読 / `--fast` = 基準 1〜6・8 の自動発動を無効化（7 のプロセス由来シグナルのみ生かす）。両方が同時に指定された場合は、矛盾する指定としてどちらを採るかを散文提示で確認してから進む。

## 並列と進捗

- サブエージェント経路では、ファイル領域が重ならない独立タスクのみ 1 メッセージで並列起動する。並列させる編集タスクの本数は 2〜8 の範囲で指揮者が判断する（上限 8。各タスクの実装奏者とレビュー奏者は直列に動くため本数には数えない。指揮者の検収が追いつく範囲に抑える）。重なる可能性があれば直列。
- 3 タスク以上に分割した場合、タスク管理機能がある環境（Claude Code では TaskCreate 等の Task ツール）では進捗をタスクとして管理する。

## git 規律

指揮者・奏者ともコミットしない。変更は作業ツリーに累積し、コミットはユーザーの指示があった場合のみ行う。タスク連番はセッション内でタスクを起こした順に 1 から振り、差し戻し後の再委譲は同じ連番を使う（ペイン経路の push ラベルも同じ連番を参照する）。非 git 環境では、連番ごとに最初の委譲の前に1回だけ対象ファイルをプロジェクト直下の `.maestro/backup/<タスク連番>/` へ元の相対パスを保って複製し（再委譲では取り直さない）、そのパスを報告する。バックアップはモード解除時に、経路を問わず削除対象のパスと中身を示して散文提示で削除可否を確認し、承認を得た場合のみ削除する（ペイン経路では `pane-route.md` の `.maestro/` 削除確認に含める）。

## 失敗時のエスカレーション

「失敗」は、奏者がタスクを完了できなかった場合（サブエージェント返却規約の再送上限を超えても報告が届かない場合を含む）と、レビュー・検収で差し戻した場合（調査タスクの根拠欠落による差し戻しを含む）のいずれも 1 回と数え、回数は同一タスク（同じタスク連番）ごとに累積して当該タスクの合格で打ち切る（失敗の数え方の正本は本節）。

失敗を1回数えた時点で本スキル同フォルダの `escalation.md` を Read し、累積回数に応じた手順（再委譲・深査読・ユーザーへの相談と一時解除）に従う。

## 最終報告

タスク群の完了時に報告する: 実施タスク一覧（奏者数・並列/直列の別）／検収結果（標準/深査読の別・差し戻し回数）／テスト・検証の最終状態／未解決点・要確認事項。
