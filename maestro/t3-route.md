# maestro T3 経路

ハーネス指定のロールをペイン経路で立てられなかった場合にのみ読む、T3 経路（T3 Code の委譲ツールで奏者を立てる経路）固有の規定の正本（どの場合に読むかは SKILL.md「奏者経路の確定」が定める）。SKILL.md の「散文提示」等の定義を引き継いだ同一コンテキストで適用する。

共通手順（委譲ツールの存在確認・委譲先の検証・委譲・結果の受け取り・質問と承認待ちへの対処・追送・中止）の正本は t3-harness であり、本書は t3-harness の利用スキルとして採用条件と呼び出しパラメータを定める。

## 採用条件

次の条件をすべて満たした場合のみ、ハーネス指定のロールを T3 経路で立てる。

1. t3-harness の SKILL.md を Read できる。解決順: `../t3-harness/SKILL.md` → 実行ハーネス自身のスキルディレクトリをプロジェクト側 → グローバル側の順（Claude Code: `.claude/skills/` → `~/.claude/skills/`、Codex: `.agents/skills/` → `~/.agents/skills/`。他ハーネス用のディレクトリは探さない）。
2. t3-harness の「前置きゲート」が、7つの能力の存在を確認して能力一覧を返す（「T3 経路は不成立」を返さない）。
3. **起動時検証**: ハーネス指定の全ロールの指定値が、t3-harness の「委譲先の確定と検証」を通る。同節が中止または散文提示での再指定となる場面（非対応の CLI名、委譲できない provider、モデル照合の不一致、エフォートの許容値外等）は、すべて理由と候補（得られれば）を示して maestro の起動を中止する（再指定は求めず、ユーザーが引数を直して再起動する）。同節が「委譲先は実行中と同じ provider」を返したロールも起動を中止し、「実行中と同じ provider は T3 経路で立てられない。モデル指定（`<model>[@<effort>]`）に直せば、サブエージェント経路で同じモデルを起用できる」と案内する。

条件1または2を満たさない場合は T3 経路の不成立として SKILL.md「奏者経路の確定」の中止の規定に戻る。条件1を満たさない場合は「T3 Code 上で使う場合は `npx skills add tmstack-io/agent-skills --skill t3-harness` で t3-harness を導入できる」を案内に添え、条件2を満たさない場合は t3-harness が返した無かった能力を案内に添える。

完了条件: 3条件をすべて満たしてハーネス指定の全ロールの provider・モデル ID・エフォート（指定時）が確定している。または起動を中止している。

## 運用

T3 経路のロールへの委譲は t3-harness の規定に従う。呼び出しパラメータ（t3-harness の全項目）:

- **委譲先**: 採用条件3を通ったロールの確定値（t3-harness の是正があれば是正後の値）。
- **ブリーフ**: SKILL.md「委譲ブリーフ」の全項目。全文を委譲の本文に書く（ファイルには書かない）。本書の「委譲の受け渡し」の一行を添える。言語はユーザーとの対話言語とする。
- **待ち方**: 完了通知待ち（指揮者は委譲したらターンを終え、ユーザーとの対話を続けながら完了通知で結果を受け取る）。
- **書き込み範囲**: ロール別に定める。implement 奏者はブリーフの対象ファイルと、検証コマンドの実行が書き出す生成物のうちブリーフに明記したパス。review 奏者と explore 奏者は「書き込みなし」（review 奏者の検証コマンドの実行が書き出す生成物のパスがブリーフに明記されていれば、そのパスだけを書き込み範囲とする）。
- **事後検査**: git リポジトリでは、委譲の前と結果の受け取り後に、変更済み・未追跡の全ファイルのパスと内容ハッシュの一覧（`git status --porcelain -uall` の各パスに `git hash-object` の値を添えたもの。削除済みのパスは「無し」と記録する）を取り、パスが増えたものとハッシュが変わったものを増えた差分とする。増えた差分から実行中の他タスクの対象ファイルを除いたものが書き込み範囲に収まっているかを確かめる。収まっていなければ、範囲外のパスをユーザーに報告し、検証の失敗として扱う。非 git 環境では検査できない旨を当該タスクの検収結果に明記する。
- **結果の形式**: ブリーフの報告フォーマット（ロール別。正本は SKILL.md「委譲ブリーフ」）。
- **識別子**: `maestro-<タスク連番>-<ロール>-<回次>`（ロールは implement / review / explore。回次は、同じタスク連番・ロールで新しく起こした委譲の通し番号。追送では元の識別子を引き継ぐ）。
- **失敗規律**: 委譲の起動の失敗・子の失敗・検証の失敗は、SKILL.md「失敗時のエスカレーション」の失敗1回として数え、同節の規定（`escalation.md`）に従う。同一ターン待ちは使わないため、その時間切れは起きない。同時実行の上限を理由とする起動の拒否は失敗に数えず、「並列の条件」の保留に従う。
- **並列の条件**: SKILL.md「並列と進捗」がサブエージェント経路のロールに定める条件（編集タスクはファイル領域が重ならない独立タスクのみ並列にする等）を、T3 経路のロールにもそのまま適用する。委譲の起動が同時実行の上限を理由に拒否された場合も、同節の保留の規定に従う。
- **追送の可否**: implement 奏者への差し戻し後の再委譲に限り、同じタスク連番の子へ追送する（前の文脈を保たせるため）。review 奏者と explore 奏者への委譲、および新しいタスク連番の委譲は、毎回新しい委譲で行う。

T3 経路に成果物置き場とペインは無い。`.maestro/` は、非 git 環境のバックアップ（SKILL.md「git 規律」）にだけ使う。

品質ゲートのレビュー奏者は、実装奏者とは別の新しい委譲で立てる。届いた完了通知は、散文提示への回答として扱わない。

## 委譲の受け渡し

全ロールの奏者へのブリーフには「独立して進められる作業は、あなたのハーネス自身のサブエージェントを同時実行上限の範囲で活用してよい（編集を並列にするのはファイル領域が重ならない作業に限る。サブエージェントへの指示には、本ブリーフの書き込み範囲を引き継ぐ）。T3 Code の委譲ツールでの再委譲はしない」の一行を添える。

## セッション途中の変更

`restart.md` が `pane-route.md` の採用条件・運用を参照する箇所は、T3 経路のロールでは本書の「採用条件」「運用」に読み替える。値（ハーネス・モデル・エフォート）が変わったロールは、次の委譲から新しい値で委譲する。閉じるペインは無く、実行中の委譲はそのまま結果を受け取る。

## モード解除と最終報告

SKILL.md「モード解除」の手順1で打ち切る委譲は、t3-harness の「中止と後始末」で止める。SKILL.md「最終報告」とモード解除の報告には、T3 経路で起動した全委譲の識別子と子スレッドのリンクを添える（子スレッドは削除しない）。

完了条件: 動かし続ける理由の無い委譲がすべて止まっており、T3 経路で起動した全委譲の子スレッドのリンクを報告している。
