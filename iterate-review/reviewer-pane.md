# iterate-review ハーネスペイン経路の成立条件と起用（正本）

SKILL.md「レビュアーの解決」経路2のポインタから読まれる。tui-harness が見つかった場合に、次の全条件を満たすときに経路2が成立する（復旧手順は SKILL.md 側が持つ。各条件の縮退先・中止の別はこのファイルが正本）:

- `mux.sh detect` が検証済みバックエンドを返す。返らなければ、`--cli` が指定されていれば縮退せず TUI マルチプレクサの要件を示して中止し、未指定なら経路③へ縮退する。
- 実行中（著者側）のモデル系統を tui-harness「異系統委譲」の実行中の系統の規則で確定する（Claude Code / codex 等の単一系統ハーネスでは静的に確定し、確認は不要。特定できなければ散文提示でユーザーに確認する）。
- `catalog.sh probe` が ok かつ `catalog.sh models <CLI名>` でモデル一覧を取得できるハーネスから、`--cli` が無ければ散文提示で1体を選んでもらう。この候補が1つも無ければ経路③へ縮退する。明示指定されたハーネスがいずれかの条件を満たさなければ、縮退せず理由と復旧方法を示して中止する。
- モデル未指定（`=` 省略）なら、確定済みハーネスのモデル一覧を散文提示して選んでもらう（実行中と異系統のモデルを優先候補として示す）。指定値を含むモデルの検証は tui-harness の「委譲先の確定と検証」に従い、系統の確定は同「異系統委譲」に従って `catalog.sh family` で系統を得る。
- 系統が実行中と同一になった場合: 異系統のモデルを持つ候補が（同 CLI の一覧内を含め）他にあれば、その候補を散文提示で示して再指定を求める。カタログの全候補に異系統のモデルが無い場合のみ、SKILL.md「レビュアーの解決」の同系統査読の明記義務に従って続行する。

成立後、SKILL.md Step 1 の一時ディレクトリ作成後（Step 2 の初回委譲の直前）にハーネスをペインで起用し、ループ中は**同一ペインへ追送**して文脈を保持する（ペインの文脈と契約の却下履歴は重複するが、両方を維持する — 契約はセッションを跨ぐ再開の正本、文脈は説明コストの削減）。呼び出しパラメータ: 成果物置き場＝SKILL.md Step 1 で作る本スキル専用の一時ディレクトリ（ブリーフ・応答ファイルもここに置く）、push ラベル＝`ir-review`、裁定スコープ＝成果物置き場＋通信規約の push。レビュー対象が差分ファイル等の一時領域にある場合はそのパスへの読み取りも許す。ハーネスの起動 cwd はプロジェクトルート。

**失敗規律**: tui-harness が「呼び出し側の失敗規律に従う」と定める場面（受理の再送・やり直しの上限超過、回答/報告ファイルもペイン上の回答本文も無い回収不能、指揮者裁定の範囲外要求）を1回の失敗と数え、同一ラウンド内で同一ペインへ同じブリーフを1回だけ再送する。再送も失敗したら「失敗上限消化」として SKILL.md「レビュアーの解決」末尾の停止規定に従う。再送が発生したラウンドは SKILL.md Step 3 のスコアボードに付記する。
