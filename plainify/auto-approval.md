# plainify 自動承認（`--auto`）の規定（正本）

plainify の承認方式のうち自動承認の正本。引数に `--auto` が含まれる起動（他スキルが本スキルを Read して同一コンテキストで適用する参照利用を含む）では、手順1に入る前にこのファイルを読了し、以下に従う。SKILL.md と言語別規則にある「自動承認では〜」の記述は、この規定を当該場面に当てはめた挙動であり、肩代わりの範囲の正本はこのファイルにある。

## 引数の解釈

- **`--auto`**（値なし）: 言語別規則が規定する整形前の確認を行わず、ユーザーの回答の代わりに次の順で確定して整形に入る。
  1. 呼び出し側が確認事項の値（例: 日本語の文体）を宣言して渡していれば、その宣言を確定値とする。
  2. 宣言が無ければ、言語別規則ファイルが定める**自動確定規則**で確定する（各言語別規則ファイルの「整形前の確認」の節が持つ）。
- `--for <読者>` と併用できる（併用時も読者の指定は必須で、無ければ自動承認でも読者を尋ねて止まる）。
- `--auto` に値を付けた場合は、整形を始めず正しい形（値なし）を示して中止する。

## 肩代わりする範囲

- 言語別規則の整形前の確認（日本語の文体判定等）。

## 肩代わりしない範囲

- **入力の不在**: 入力が無い起動は自動承認でも「入力」の規定どおり尋ねて止まる。
- **`--for` の読者の不在**: 読者の記述が無ければ自動承認でも尋ねて止まる（既定モードへは倒さない）。
- **出力先**: 自動承認でもファイルや GitHub への反映は行わない（整形結果をテキストで返す。反映は呼び出し側またはユーザーに委ねる）。

## 出力の義務

自動確定した確認事項は、確定した値と根拠（呼び出し側の宣言 / 自動確定規則のどちらで確定したか）を一言で添える。添える位置は SKILL.md 手順5「出力」の規定に従う（参照利用では整形結果ではなく呼び出し側の報告に載せる）。

## 想定する使い方

他スキルが本スキルを Read して同一コンテキストで適用する参照利用で、回答を返すユーザーがいない場合（サブエージェントへの委譲を含む）に用いる。呼び出し側は、確認事項の値を宣言できるなら宣言して渡し、宣言しない場合は自動確定規則で決まることを前提に、自身の承認ゲートで人の確認を取る。現行例: pr-comment 同梱の公開整形契約の第2段、smart-commit のコミット本文整形、deep-pr-review の統合レビュー明快化、impact-investigation の `--for` レポート。
