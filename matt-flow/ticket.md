# matt-flow チケット実装（`--ticket`）

`--ticket` で起動した場合に、SKILL.md の Step 0 の完了後に読む手順の正本。SKILL.md の「散文提示」「上流スキルの読み替え」等の定義を引き継いだ同一コンテキストで適用する。

1. **チケットの取得**: 渡された値が既存ファイルのパスなら、setup の有無を問わずそのファイルを読み、親 spec は同じ `.scratch/<feature-slug>/`（チケットファイルの2階層上）の `spec.md` を読む。番号なら、setup 済みは `docs/agents/issue-tracker.md` の手順でチケットを取得して親 spec をチケットが参照する親 issue から同じ手順で取得し、未 setup は `.scratch/*/issues/<NN>-*.md` に一致するファイルを探す（複数あれば候補を散文提示で確認する）。チケットまたは親 spec が取得できない場合（指定パスが無い、該当が0件、`spec.md` が無い等）は、取得を試みた場所を示して中止する。チケットの題名を示してから進む。完了条件はチケットと親 spec の取得。
2. **ブロッカー**: チケットの「Blocked by」に挙がるチケットが未解決（`Status:` やトラッカー上の状態で判定）なら、未解決のものを示して「中止する（推奨。ブロッカーを先に実装するため）／このまま進める」を散文提示で確認する。完了条件は進むか中止するかの確定。
3. **seam と検証方法**: 親 spec の Testing Decisions とチケットの受け入れ基準から、このチケットで扱う seam と検証方法を SKILL.md の Step 3 と同じ3分類で提示し、散文提示で確認して、承認された内容で確定する（spec ファイルは書かない）。完了条件は seam ごとの検証方法の確定。
4. **実装とレビュー**: SKILL.md の Step 4 と同じ手順で行う。完了条件も Step 4 に従う。
5. **チケットの状態**: チケットの `Status:` やトラッカー上の状態は変更しない（コミット後にユーザーが更新する）。最終報告での扱いは SKILL.md の「最終報告」が定める。
