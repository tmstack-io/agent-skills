# 公開整形契約（正本）

pr-comment / pr-recheck が投稿文面を**公開整形**（publish-polish → plainify の2段の逐次適用）
するときの共通規定。両スキルはこのファイルを参照する。各スキル固有の三点宣言
（想定読者・配布形態・約束するもの）・適用要点・保護対象の列挙は各 SKILL.md 側にあり、
本契約には含まれない。

## 整形スキルの解決手順

`publish-polish/SKILL.md` と `plainify/SKILL.md` をそれぞれ次の順で探して Read する —
(1) 参照するスキルの隣（`../publish-polish/SKILL.md`・`../plainify/SKILL.md`）、
(2) 実行ハーネスのスキルディレクトリのプロジェクト側 → グローバル側。
どちらか一方でも見つからなければ処理を開始せず中止し、導入手順
（`npx skills add tmstack-io/agent-skills --skill publish-polish` /
`--skill plainify`）を案内する（未整形の内部語混じり文面で投稿・返信する縮退はしない）。
plainify の言語別規則ファイルは、plainify の「言語の扱い」の節に従って解決する。

## 契約

整形は**2段の逐次適用**とする。第1段の適用で文面を確定させてから、その文面を原文として
第2段を適用する（両段の規則を1回の書き換えで同時適用しない）。

**第1段 — publish-polish**: 解決した publish-polish の**判定基準（削除候補のカテゴリ判定）と
磨き込み基準のみ**を文面に適用する（磨き込み基準は publish-polish 側では `--style` 指定時
限定だが、部分適用では常に適用する）。

**第2段 — plainify**: 第1段適用後の文面に、解決した plainify の**既定モード（意味厳守）**の
規則を適用する（`--for` モードは使わない）。文面の言語を問わず常に適用する — 言語の分岐は
plainify が内部で解決する（言語別規則が未収録の言語だった場合は、その旨を投稿文面ではなく
ユーザーへの報告に記す）。plainify の内部検証（照合パス）は第1段適用後の文面を原文として
実施する。

両段に共通の規定:

- publish-polish の「フロー」（対象列挙・提案レポート・承認・ファイル書き換え）は既存ファイルの
  書き換え用なので**実行しない**。フロー冒頭の「公開の姿の確認」のユーザーへの質問も行わず、
  適用するスキル側が**想定読者・配布形態・約束するもの**の三点を宣言して代える。
- plainify の言語別規則が規定する**整形前のユーザー確認（日本語の文体判定等）は行わない**。
  日本語文面で文体（です・ます / だ・である）が混在する場合は、確認せず敬体（です・ます）へ
  統一する。
- **漏えいの疑いは投稿を保留する**: publish-polish の「要対応」区分（クライアント名・内部 URL・
  認証情報など漏えいの疑いがある記述）に相当する内容を文面に検出したら、**書き換えず**当該分の
  投稿を保留する。該当箇所と疑いの理由を示し、「修正して投稿する」「見送る」の二択を空行区切り・
  番号付きの散文で本文に提示し（各選択肢は採用後に何が起きるかが再読なしに分かる完結した文で
  書く）、ツールを呼ばずターンを終了して回答を待つ。「修正して投稿する」が選ばれた場合は、
  書き換え後の文面を before→after で提示して承認を得たうえで、**2段を通してから**投稿対象に戻す。
- **保護対象は一字一句保持する**（何が保護対象かは適用するスキル側が列挙する。両段とも同じ
  保護対象に従う）。
- **実体を変えない**: 主張・判定・根拠・条件・例外・推奨の数と強度を増減させない。
  公開整形は視点の変換と明快化であり、内容の発明ではない。
- **各投稿を単体で成立させる**: 他の投稿や「上記の指摘」への参照を書かない
  （読者は別々の行で読む）。
