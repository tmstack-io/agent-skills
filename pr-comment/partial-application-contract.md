# 公開整形契約（正本）

pr-comment / pr-recheck / pr-respond が投稿文面を**公開整形**（publish-polish → plainify の2段の
逐次適用）するときの共通規定。各スキルはこのファイルを参照する。各スキル固有の三点宣言
（想定読者・配布形態・約束するもの）・適用要点・保護対象の列挙は各 SKILL.md 側にあり、
本契約には含まれない。

## 整形スキルの解決手順

`publish-polish/SKILL.md` と `plainify/SKILL.md` の解決順・見つからない場合の中止と導入手順は、本契約を参照する各 SKILL.md の前置きゲートが持つ（規約上、他スキルの解決順と復旧手順の文言は各スキルのルートに置く）。

## 契約

整形は**2段の逐次適用**とする。第1段の適用で文面を確定させてから、その文面を原文として
第2段を適用する（両段の規則を1回の書き換えで同時適用しない）。

**第1段 — publish-polish**: 投稿候補の文面を1候補1ファイルで一時領域（OS の一時ディレクトリに
`mktemp -d` で作る適用スキル専用のディレクトリ）に書き出し、そのディレクトリを対象パスとして、解決した
publish-polish を **`--auto 全件 --style`** で実行する（Read して同一コンテキストで適用する。`--auto` の
規定は publish-polish 同梱の `auto-approval.md` が正本で、publish-polish の SKILL.md の指示どおり走査前に
読了する）。適用スキル側の三点宣言（想定読者・配布形態・約束するもの）を publish-polish [1] の①〜③の
確定値として渡し、適用スキル固有の適用要点・保護対象を判定基準に加えて適用する。publish-polish の [5] が
書き換えた各ファイルの内容を第1段適用後の文面とする。publish-polish の報告（適用・未適用・要対応の未対処）
は投稿文面に含めず、適用スキルの報告に載せる。

**第2段 — plainify**: 第1段適用後の文面に、解決した plainify の**既定モード（意味厳守）**の
規則を適用する（`--for` モードは使わない）。文面の言語を問わず常に適用する — 言語の分岐は
plainify が内部で解決する（言語別規則が未収録の言語だった場合は、その旨を投稿文面ではなく
ユーザーへの報告に記す）。plainify の内部検証（照合パス）は第1段適用後の文面を原文として
実施する。

両段に共通の規定:

- publish-polish の「フロー」は一時ファイルに対して全工程を実行する。「公開の姿の確認」のユーザーへの
  質問は自動承認により行われず、適用するスキル側の**三点宣言**が①〜③の確定値になる。一時ディレクトリ・
  `publish-polish-findings.json`・`publish-polish-backup/` は、適用スキルの後始末で削除する（後始末の規定が
  無いスキルは投稿の完了または中止の後に削除する）。
- plainify の言語別規則が規定する**整形前のユーザー確認（日本語の文体判定等）は行わない**。
  日本語文面で文体（です・ます / だ・である）が混在する場合は、確認せず敬体（です・ます）へ
  統一する。
- **漏えいの疑いは投稿を保留する**: publish-polish の報告で「要対応」（クライアント名・内部 URL・
  認証情報など漏えいの疑いがある記述。自動承認では「未対処」として残る）に挙がった候補は、**書き換えず**
  当該分の投稿を保留する。該当箇所と疑いの理由を示し、「修正して投稿する」「見送る」の二択を散文提示で確認する
  （散文提示の定義は本契約を参照する各 SKILL.md の正準ローカル定義に従う）。「修正して投稿する」が選ばれた場合は、
  書き換え後の文面を before→after で示し、「この文面で投稿する」「見送る」の二択を散文提示で確認したうえで、
  **2段を通してから**投稿対象に戻す。
- **保護対象は一字一句保持する**（何が保護対象かは適用するスキル側が列挙する。両段とも同じ
  保護対象に従う）。
- **実体を変えない**: 主張・判定・根拠・条件・例外・推奨の数と強度を増減させない。
  公開整形は視点の変換と明快化であり、内容の発明ではない。
- **各投稿を単体で成立させる**: 他の投稿や「上記の指摘」への参照を書かない
  （読者は別々の行で読む）。
