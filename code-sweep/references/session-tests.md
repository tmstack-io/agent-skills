# code-sweep セッション生成物のテスト規定（正本）

SKILL.md フェーズ5のポインタから、セッション生成物を対象とした場合（フェーズ1で確定）にのみ読まれるテスト規定の正本。複製・見送り・結果報告の語は SKILL.md フェーズ5の定義に従う。

## ベースライン（適用前の準備で、書き換えを始める前に行う）

プロジェクトのテストコマンド（package.json の scripts・Makefile のターゲット・CI 設定等から特定）が存在すれば 1 回実行し、失敗を記録する（ベースライン）。テストが存在しない場合、または対象がリポジトリ外のファイルのみの場合はスキップし、その旨を結果報告に明記する。

## 再実行と原因特定（適用後の検証で、複製との diff 確認の後に行う）

テストを再実行し、適用前の準備で記録したベースラインに無い新たな失敗がないことを確認する。新たな失敗が出た場合は、失敗したテストが参照するファイルを複製から復元したうえで、そのファイルの承認済み候補を確信度の低い順に1件ずつ除外して再適用・再テストし、新たな失敗が消えた候補を原因として取り消し、結果報告に明記する。原因を1件に特定できない場合は当該ファイル全体を複製から復元し、そのファイルの候補をすべて「見送り」として報告する。失敗したテストから対象ファイルを特定できない場合は、変更した全ファイルを複製から復元し、承認済み候補をすべて「見送り」としてテスト出力とともに結果報告に明記する。ベースラインをスキップした場合は再実行もスキップし、その旨を結果報告に明記する。 候補を除外して再適用したファイルには、再テストの前に SKILL.md フェーズ5「検証」の 1・2 を再度行う（失敗時の扱いも同じ）。
