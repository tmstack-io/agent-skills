### セッション生成物への追補（書かれたばかりのコードへの追加基準。上記基準と矛盾する場合は本追補が優先）

担当ファイルはこのセッションで作成・変更されたばかりのコードである。次を追加で適用せよ。

**保護対象の変更**: 「現役の `TODO` / `FIXME` / `HACK` / `XXX`」の保護は適用しない。TODO 類は `category: "D"` の候補として返す。ただし confidence は **必ず 40–74（要確認）の範囲**とする（未実装の存在を示す TODO を無断で消させないため）。`NOTE` は引き続き保護。

### カテゴリ D: 自明・冗長コメント

直後のコードを読めば分かる内容をなぞるだけのコメント。書かれたばかりのコードでは AI 生成の癖として混入しやすい。

- **90**: `// カウンタをインクリメント` の直後が `count++;` → コードの逐語訳。
- **85**: `// ユーザーを取得する` の直後が `getUser()` 呼び出し → 関数名の反復。
- **50**: 処理ブロックの区切りコメント（`// --- バリデーション ---` 等）→ 冗長に見えるが可読性目的の可能性がある。要確認。
- **返却しない**: 「なぜ」を説明するコメント、非自明なアルゴリズム・単位・制約の説明 → rationale。保護。
