# 軽量な異系統相談を合議から分離し別席相談として新設する

Status: accepted

roundtable は主題を3席の合議に掛け、相互批評と収束判定を経て verdict へ統合する。既存の利用側スキルはこれを工程の決まった位置に組み込んでおり、掛かるのは「エージェントが作った案」である。一方で実測された需要は別物だった — 作業の途中でユーザーが実行中のエージェントの提案に納得できず、その場で別のモデルの見解が欲しくなる場面である。この場面の主題はユーザーが抱えた問いであり、掛かる位置は工程のどこでもありうる。roundtable をそのまま当てると、3席・最大5ラウンドの儀式と工程固定の制約を、一往復で済む相談に課すことになる。

**別席相談**（sidebar）を新設し、合議とは別スキルとして分離する。区別の軸は2つ — 主題（案の審査か、問いへの独立回答か）と、工程との結び付き（固定位置か、非依存か）である。別席相談は既定1席、ラウンド管理と収束判定を持たず、どの作業の途中からでも呼べる。

分離にあたり、合議と異なる3つの規律を持たせた:

- **素通し** — 回答を統合・要約・並べ替えせず全文で提示し、優劣はユーザーに求められたときだけ述べる。統合するのは、ユーザーが納得できなかった当の実行エージェントであり、統合の過程で別席の異物感が削られて元の案へ回帰する。実行エージェントが添えるのは差分注記に限る。
- **無記名** — 手元の案は出どころを伏せて渡す。roundtable がラウンド2以降で回答者名を伏せるのと同じ権威バイアス対策であり、出どころを知った委譲先は遠慮するか、否定するために否定する。
- **同系統を起用しない** — 委譲先のモデル系統が実行中と一致する候補は選ばず、候補が無ければ中止する（縮退しない）。実行中のエージェントの答えに納得がいかない場面のためのスキルであり、同系統は同じ癖の答えを返す。ADR 0010 の「同系統の許容可否はスキル別」に従う本スキルの規定である。

検討した代替案: (a) roundtable の適用位置を工程非依存へ広げる — 却下。合議の重さは残ったままで、利用側スキルが持つ「いつ掛けるか」の規定も同時に緩むため、審査としての品質保証が弱まる。(b) roundtable に軽量モード（1席・0ラウンド）を足す — 却下。1つのスキルが「審査して統合する」と「素通しする」という相反する出力規律を抱えることになり、単一正本が保てない。

帰結: TUI マルチプレクサに依存するスキルが1つ増える。記録は `.sidebar/` に永続保存し、`.roundtable/` とは分ける（合議の議事録と混ざると、どちらの重みの記録か判別できなくなるため）。利用側スキルの工程へは組み込まないため、既存スキルへの変更は生じない。
