# tandem の異系統必須を撤廃し、明示起動スキルを代理起動する代理実行型を加える

Status: accepted

明示起動専用のスキル（`disable-model-invocation: true`）はモデル自身が起動できないため、複数の PR を deep-pr-review で順にレビューするような反復を、管理役のエージェントに任せられなかった。ペインの入力欄へ起動文（Claude Code では `/<スキル名> <引数>`）を送ると、ペイン側のハーネスには人間の入力と区別できない名指し起動として届くため、この経路は技術的には成立する。問題は「起動＝重い操作の実行許可」というフラグの意図を管理役がすり抜けてよい条件だった。

**tandem に第3の完遂条件の型として代理実行型（`--invoke`）を加え、代理起動を許す条件を「依頼文でユーザーが名指ししたスキルに限る」と定めた。** 起動の意思はユーザーに属し、著者は依頼文の対象から起動文を組み立てて入力を代行するだけで、どのスキルを使うかは選ばない。スキルが求める承認・回答は、ユーザーが方向性を指示している場合だけ著者がそれに基づいて答え、指示が無ければユーザーに確認する。裁定スコープ外の承認ダイアログも拒否せずユーザーに確認する。

あわせて、**tandem の「新設時は異系統必須」を撤廃した**（ADR 0009・0010 の異系統委譲の方針を tandem について覆す）。代理起動ではペインに求めるのが別の視点ではなくスキルの実行であり、Claude Code から Claude Code のペインへ送るのが主用途になるため。相談の型（LGTM 収束型・回収統合型）では、系統の確定と表示を残し、異系統の候補を推奨として示す。

## Considered Options

- **代理起動の専用スキルを新設する**（例: PR の一括レビュー専用）— 却下（ユーザー判断）。スキルを増やさず、ペインとの中継を既に担う tandem に置く。
- **代理起動の後をユーザーへ引き渡す片道型** — 却下。sidebar の片道委譲と役割が重なり、管理役に反復を任せる目的を満たさない。
- **著者が自分の判断でペインの問いに答える** — 却下。PR への投稿のような外部への書き込みの基準はユーザーが持つべきで、方向性の指示が無い問いは確認に回す。
- **異系統必須を代理実行型だけ例外にする** — 却下（ユーザー判断）。tandem 全体で同系統を認め、相談の型では推奨で異系統へ誘導する。

## Consequences

- 作業単位（互いに独立した対象ごとのまとまり）の区切りで文脈リセット（`/clear`）を送るため、単位をまたいで前の出力に依存する起動文の並びは作れない。同じ単位の起動文は同じセッションで続けて実行する。
- `--max-rounds` は代理実行型では起動文1つあたりの送信回数の上限で、依頼全体の起動文の数は制限しない。
- スキルの結果はペイン画面から回収するため、画面読みの上限（800 行）を超える出力は回収できず、失敗規律で停止する。必要になれば、起動される側のスキルに結果のファイル保存を加える調整を別途行う。
- CONTEXT.md に「代理起動」を追加した。
