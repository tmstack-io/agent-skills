# 選択肢の提示を散文提示に統一し選択式 UI ツールをフォールバックからも外す

ADR 0001 は選択式確認（Claude Code の AskUserQuestion 等）を「返信が適用範囲として解釈できない場合のフォールバック」に降格し、有効性が確認できたら設計規約へ昇格させるとしていた。実運用でターン終端プロトコルの有効性が確認された一方、選択式 UI ツールは残したフォールバック経路でも「ツールが呼ばれず選択肢が提示されないままターンが終わる」機能漏れを起こし、ラベル数語に圧縮された選択肢文面は内容の吟味を要する選択で読者に内容を正しく理解させられなかった。そこで本決定で規約へ昇格させると同時にさらに進め、フォールバックも散文での選択肢再掲＋テキスト回答待ちに置き換えて、選択式 UI ツールの使用を全廃した。0001 のターン終端プロトコル（指摘の全件本文出力 → ツールを呼ばずターン終了 → 返信そのものを承認とする構造）は存続する。文面要件（空行区切り・番号または見出し・推奨明示・読者想定・術語への一言説明）の正本は AGENTS.md のスキル設計規約。

## Considered Options

- **内容吟味型の選択のみ散文化し、軽量確認（モード判定・保存先確認等）は選択式 UI を維持する案**: 線引き自体が曖昧な判断ゲートになり（規約の二値化原則に反する）、機能漏れは軽量確認でも起こるため却下。

## Consequences

- 執行機構として skill-refine の査読基準 D にモード非依存の査読項目を追加した。既存スキルの選択式 UI 規定（decruft / publish-polish / impact-investigation / session-to-prompt / client-docs / slack-research）は次回の `/skill-refine` 査読で指摘され、承認を経て散文提示へ移行する（遅延適用）。
- 同内容の決定は claude-skills リポジトリの docs/adr/0006 にも記録している（規約の正本が各リポジトリにあるため、ADR も各リポジトリが自前で持つ）。
