# 別席相談を回答を持ち帰る往復から投げて引き渡す片道に改める

Status: accepted

ADR 0011 で新設した別席相談（sidebar）は、問いを別系統のモデルへ投げ、回答をファイルで回収して素通しで提示し、差分注記を添え、追問はペインへ再送し、終わりにペインを閉じるかを確認する — という往復モデルで設計した。実際に使ってみると、ユーザーの動きは「文脈込みで問いを別ペインの LLM に投げ、その回答をペインの中で読み、そのままその LLM と壁打ちし、確定した答えを自分で持って帰る」だった。実行エージェントが回答を回収してユーザーに提示する工程は、ユーザーがペインで既に読んでいるものを二重に見せるだけで、その後の追問・差分注記・終わり方の確認も、ユーザーがペインで直接やっていることの重複だった。

**sidebar を片道モデルに改める。** 責務は「セッションの文脈（問い・手元の案・決定事項・却下事項・参照ファイル）を添えたブリーフをペインへ送り、受理を確認する」までとし、以後のペインでの対話・承認ダイアログへの応答・ペインを閉じる判断はユーザーに引き渡す。回答ファイル・push・pull 安全網・指揮者裁定・クローズは行わない。この形態を tui-harness に「片道委譲」として一般化して置き、sidebar はそれを明示して適用する。

判断の要点:

- **完了は受理確認まで、送りっぱなしにはしない** — tui-harness の実測で TUI 初期化直後の送信が丸ごと捨てられる事故が既知であり、受理を確認しないと「投げた」と言えない。一方で最初の回答を待つと往復モデルに戻る。
- **文脈の構造化と無記名は維持する** — 「却下したことを知らないと退けられた案を持ってくる」等の実害に基づく設計で、往復か片道かによらず価値は同じ。ブリーフには「回答はこのペインで述べよ、以後の質問はこのペインで直接届く、ファイル書き出しと完了通知は不要」の引き渡しの一文を足し、相手のモデルが通信規約の作法で動こうとするのを防ぐ。
- **記録は残さない** — 回答がペインの中にしか無い以上、`.sidebar/` にブリーフだけを永続保存しても「何を聞いたか」しか引けず半端。ブリーフは一時領域に置き、ペイン自体が壁打ちの記録になる。
- **続用は差分で** — 前回のペインが生きていれば、前回ブリーフを基準に変わった項目だけを添えて追問できる（Claude 側で話を詰めた後、その分だけを開きっぱなしの相手に渡す動き）。前回ブリーフが一時領域から消えていれば全量を投げ直す。
- **席は1つ、同系統は起用しない** — 壁打ちは1対1で、複数ペインを同時に相手にする用途は実測に無い。「実行中の答えに納得がいかない」場面のスキルである動機は変わらないため、同系統への縮退はしないまま。

検討した代替案: (a) 往復モデルを残し「回収しない」オプションを足す — 却下。1つのスキルが「回収して提示する」と「引き渡す」の両方を抱えると、手順の半分が条件分岐になり簡素化にならない。(b) sidebar 側で tui-harness の手順を個別に除外列挙する — 却下。tui-harness に手順が増えるたび除外リストが古びる。片道委譲は単発利用の「他ハーネスをペインで併走させたい」にも使える一般概念で、正本は tui-harness が持つ。

帰結: 手順は7から5へ減り、記録の扱い節・exclude 提案・部分失敗規定・複数席規定が消える。CONTEXT.md の「別席相談」を再定義し、「素通し」「差分注記」を削除、「片道委譲」を新設した。ADR 0011 の分離判断そのものは有効で、根拠に挙げた3規律のうち「素通し」だけが撤回される。
