# tui-harness に直送委譲を追加し、tandem の `--direct` で会話型の往復を許す

Status: accepted

tui-harness の委譲形に、往復委譲・片道委譲と並ぶ第3の形として**直送委譲**を追加した。初回はブリーフで文脈を渡し、2通目以降の指揮者の追問は直送上限（文字数）以内ならペインへ直接送り、返答はペイン画面（`mux.sh read --scrollback`）から読む。回収まで行う点は往復委譲と同じで、ペイロードは上限を超えるときだけファイル（指揮者側 `note-<n>.md`・委譲先側 `report-<n>.md`＋push）を通す。利用スキルは tandem の `--direct`（直送上限は `--max-text`、既定 1000 文字 — 実測で欠けずに届いた 1,037 文字の直下に丸めた値）で、ラウンド構造（毎回のブリーフ・応答ファイル・スコアボード・停滞ガード・`rejected.md`）を持たず、著者が終了条件（要件全反映＋直近返答に未解消指摘なし、または統合報告）を満たすまで往復する。往復は `dialog.md` に追記記録し、再開の文脈正本とする。

理由: tandem の往復は「ペイロードはファイル、ペインは信号」の原則どおり毎回ブリーフと応答ファイルを介していたが、相談役と1つの解決策を練る用途では追問が短文の連続になり、ファイルの作成・回収・ラウンド集計のオーバーヘッドが往復の内容を上回っていた。原則の根拠は「長文をペインに流し込むと壊れる」「回答をファイル以外から確実に回収できない」の2点で、前者は herdr での実測（19行 1,037 文字の複数行送信が入力欄に欠けずに入り、改行で送信されない）により上限付きで解消し、後者は画面読みの規律（表示行数より大きい `--lines`・送信エコーを基点に切り出す・切り出せなければ回収失敗として失敗規律へ）を定めることで、暗黙の縮退を作らずに扱える。原則は撤回せず、直送委譲を上限付きの明示的な例外として位置づける。

## Considered Options

- **sidebar の続用で代替する** — 却下。sidebar は片道委譲でペインをユーザーに引き渡すため、著者が中継して要件を反映し続ける tandem の用途（決まったことゲート・検証コマンド・LGTM 収束）を満たさない。
- **tandem 内だけの手順として書く** — 却下。送信長の上限・画面読みの規律・複数行送信の実測はペイン操作の知識であり、tui-harness に置かないと他の往復スキルが同じ手段を欲したときに重複する。
- **直送モードでもラウンド構造を残し、送受信の手段だけ替える** — 却下（ユーザー判断）。会話としての軽さが目的であり、ラウンドごとの集計と停滞ガードは往復の粒度に合わない。歯止めは `--max-rounds` の送信回数上限（直送モードの既定 10。1往復がラウンド型より軽く回数が増えるため、ラウンド型の 5 の倍にした）と決まったことゲートで確保する。
- **tui-harness に直送委譲を定義し、tandem の `--direct` が利用する（採用）**。

## Consequences

- 直送委譲の返答切り出しに使う画面マーカーは transports ごとに実測が要る。2026-09-15 時点で実測済みは claude（`❯` / `⏺`）のみで、他の委譲先では指揮者が画面テキストから返答を判別し、判別できなければ回収失敗として失敗規律に従う（黙って空返答にしない）。cmux バックエンドは未実測のため直送委譲を中止する。
- 直送上限を超える返答の report ファイル＋push 経路は未実測（規約として委譲先に明示しているが、実行時に失敗すれば失敗規律で停止する）。
- claude transports の trust ダイアログの既定選択が Claude Code 2.1.270 で `No, exit` に変わっていることを同時に実測し、通過手順を Down → Enter に更新した（本 ADR の主題ではないが、同じ実測で得た変更）。
- CONTEXT.md に「直送委譲」を追加した。
