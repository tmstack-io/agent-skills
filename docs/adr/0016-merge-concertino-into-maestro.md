# concertino / solista を maestro に統合し、ロールの指定値で奏者のハーネスを選べるようにする

Status: accepted

concertino（指定ロールを異系統ハーネスの編成に配役するセッションモード）と solista（その編成1ラッパー）を廃止し、セッションモードを maestro 一つにする。maestro のロールフラグ（`--all` / `--implement` / `--review` / `--explore`）の値は `<model>[@<effort>]` または `<CLI名>=<モデル>[@<エフォート>]` の2形とし、`=` を含む値だけをハーネス指定として、そのハーネスのペインを当該ロールの奏者に立てる。モデル指定のロールは従来どおりの奏者経路（サブエージェント、無ければ同系統ペイン）で動く。ペインの運用・品質ゲート・検収・失敗時のエスカレーション・成果物置き場（`.maestro/`）はすべて maestro の規定が正本である。

発端は `maestro --all opus --review codex=gpt-6.1-Sol@high` のように、maestro の起動1回で review だけを別ハーネスへ出したいという要求だった。当初は maestro から concertino を Read 参照して配役させる案で設計したが、両者は配役の規律（指揮者が編集するか・品質ゲートの有無・失敗時の扱い・検収段階・異系統の要否・implement と review の同居可否・奏者数・成果物置き場の削除方針）がことごとく異なり、併用時の優先関係を `with-maestro.md` に積み増す構造になった。maestro は既にサブエージェントとペインの両経路を持ち、ハーネス指定を受け付ければ concertino の役割をほぼ吸収できるため、規律を maestro 基準に一本化した。

## Considered Options

- **maestro から concertino を Read 参照して配役する** — 却下。両スキルの規律の相違を併用時の優先規定で埋め続けることになり、ほぼ同じ規律を持つセッションモードが2つ残る。
- **concertino を残し、規律は maestro を正本として Read させる** — 却下。concertino 固有に残るのが編成と経路だけになり、単体起動しても実質 maestro と同じになる。
- **構造を維持し、相違点を concertino 側で個別に maestro へ寄せる** — 却下。二重保守が残る。
- **concertino / solista を廃止し maestro に統合する（採用）**。

## Consequences

- 指揮者が自分でも実装しつつ一部ロールだけを外部ハーネスへ出す使い方（concertino 単体）は失われる。maestro の指揮者は常に非実装である。
- 1ロールに複数奏者を置く編成（上限4・観点分担・指摘の統合）、codex 固有オプション（`--sandbox` / `--approval` / `--approvals-reviewer`）、パート譜、concertino 内蔵のレビュー規範は廃止する。
- ハーネス指定ではモデル系統を照合しない（ユーザーの明示指定をそのまま起用する）。ADR 0010 の concertino / solista に関する同系統不許容の規定は対象スキルの消滅により失効する。implement と review の同居禁止も、maestro の三段ゲート（実装奏者→別個体のレビュー奏者→指揮者検収）が責任分界を担うため持たない。
- ハーネス指定はユーザーの明示であるため、ペイン経路の許諾ゲートはサブエージェント機構が無い環境の同系統ペイン経路でのみ発火する。TUI マルチプレクサが無い・ハーネスやモデルの検証に失敗する場合は、ハーネス指定を含む起動を中止する（モデル・エフォートの検証は起動時に行う）。
- iterate-review のレビュアー解決順から「セッションの review 配役」を削除する（レビュー契約への準拠を宣言する配役スキルが存在せず、統合前から未使用だった）。
- 用語「配役」「編成」「パート譜」「single-writer」は CONTEXT.md から削除した。過去 ADR（0004〜0012）の concertino / solista への言及は記録として本文を変更しない。
