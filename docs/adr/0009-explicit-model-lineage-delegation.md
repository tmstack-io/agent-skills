# TUI 委譲先のハーネスとモデルを明示選択する

Status: superseded by 0010

tui-harness を使う concertino、solista、deep-pr-review、iterate-review は、移管時に codex を委譲先の既定としたため、Codex 上で起動すると外側と内側が同じハーネスになる。内側の実効モデルは設定に依存するため常に同じモデルとは断定できないが、異系統性を期待する委譲で同一系統を暗黙に選ぶ余地が残っていた。これら4スキルではハーネスとモデルを起動前に明示選択し、未指定時はハーネス、モデルの順に散文提示で選んでもらう。CLI 固有の別名から推論設定等を除いたモデル同一性識別子が実行中と同じ組は拒否し、Codex から codex への委譲はモデルが異なっても拒否する。

roundtable も second 席と third 席のハーネスとモデルを起動前に確定する。roundtable は同じ CLI から異なるモデル系統を選べることが3席を成立させる場合があるため、Codex から codex を含む同一 CLI の複数利用を許し、host を含む3席のモデル同一性識別子が相互に異なることをガードとする。maestro の同系統ペインはサブエージェントを使えない環境で指揮者の働きを維持する許諾済み縮退であり、異系統委譲を目的としないため変更しない。

この決定は ADR 0006 と ADR 0007 が移管時に導入した codex 既定、および ADR 0008 の「codex ペインを異系統レビュアーの既定とする」判断を部分的に置き換える。固定既定の起動の軽さより、実行環境を問わず委譲先を再現でき、同系統委譲を起動前に検出できることを選ぶ。モデル一覧を取得できないハーネスと `auto` 等の実効モデルを起動前に確定できない指定は候補から除外し、検証不能なモデルを透過する縮退は設けない。Claude Code はモデル一覧を正確に取得できないため、API から取得した ID・表示名の一覧を `tui-harness/models/claude.tsv` に保持し、ユーザーが選んだ名称を同ファイルと照合する。新モデル発表や提供終了時はこの一覧をメンテナンスとして更新する。`claude` TUI の明示モデル起動と委譲を実測し、この静的一覧を起動前検証の正本としてペインの委譲先に加える。

## Consequences

- concertino、solista、deep-pr-review、iterate-review、roundtable は、必要な指定が無い場合に選択のための対話ターンが増える。
- 異系統委譲はモデル同一性識別子の相違で判定する。同じハーネスでも識別子が異なれば成立し、ハーネスが異なるだけでは成立を保証しない。reasoning effort 等の実行設定だけが異なる組は同じモデルとして扱う。
- Claude Code の実行中モデルは自動判定せず、静的一覧に掲載された ID または表示名の選択を必須とする。未掲載モデルは一覧を更新するまで異系統性判定に利用できない。
- 過去 ADR は当時の判断記録として変更せず、現在の実行契約は本 ADR と各 SKILL.md を正本とする。
