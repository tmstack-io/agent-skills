# 異系統判定をモデル系統の照合に置き換え同系統の許容可否をスキル別に定める

Status: accepted

ADR 0009 のモデル同一性識別子は、CLI 固有の別名からバージョン・reasoning effort 等を精密に解析して得る値であり、正しさがハーネス側の命名フォーマットの安定性に全面依存していた。実測でも、cursor-agent の `grok-4-fast` は `-fast` を実行設定として剥がされ `grok-4` に、grok CLI の同名モデルは `grok-4-fast` のままとなり、同じモデルが CLI によって別識別子になる不整合が確認された。接尾辞が実行設定か別モデルかはベンダーごとに異なる事実であり、剥ぎ取りリストの保守では原理的に追随できない。

判定単位を**モデル系統**（モデル名の先頭ファミリートークン。`claude` / `gpt` / `grok` 等。正本は `catalog.sh family`）へ粗くする。バージョン・reasoning effort・thinking・fast・`[1m]` は照合に含めず、同系統の別バージョン・別ティアは同席として扱う。これによりハーネス側の命名変更への耐性を得るとともに、異系統性の意味が「同じ学習系統のモデルは同じ間違いを再現しやすい」という本来の前提（系統レベル）に一致する。単一系統のハーネス（Claude Code → claude、codex → gpt、grok → grok）では実行中の系統が実効モデルによらず静的に確定するため、実行中モデルの特定対話も原則不要になる。Claude の静的モデル一覧は claude ペインの起動検証専用に役割を縮小し、表示名エイリアス列とヘッダーを持たない ID のみの `models/claude.txt` に簡素化する。

同系統の許容可否は、公開配布での可用性を考慮しスキル別に定める:

- **concertino / solista** — 許容しない。異系統の実行体を別ペインに立てて指揮できることがスキルの価値そのものであり、指揮者と同系統の奏者はセッション本体・サブエージェントと差が無い。異系統委譲が成立しない環境では配役を開始せず中止する。
- **iterate-review / deep-pr-review** — 異系統を優先し、カタログの全候補に異系統モデルが無い場合のみ、著者と独立したコンテキスト（同系統ペインまたはサブエージェント）での査読を、同系統である旨の明記を義務として許容する。deep-pr-review はペイン候補ゼロでもサブエージェント代替 → skip の段階縮退で完走できる。
- **roundtable** — host と同系統の CLI 席を最大1席まで許容する（その席はモデル一致まで可）。少なくとも1席は host と異系統であることを要件とし、最低2系統・3独立コンテキストを常に保証する。指定と実効の食い違いを検出するため、ペイン起用席はラウンド1後にペイン表示の実測モデルを議事録へ追記し、ガードを破ると判明した時点で円卓を停止する。

検討した代替案: (a) 剥ぎ取りリストの修正と既知モデルの例外辞書 — 却下。ベンダーの命名追加のたびに例外が増え、脆さの構造が変わらない。(b) 版レベル判定の維持＋系統ガードの追加 — 却下。二重の判定基準は説明も保守も複雑になり、版レベル判定の脆さも残る。

帰結: 同ベンダー異ティアの組（opus と sonnet 等）は同席となり選べない。codex 単独で複数席を埋める編成は不可になり、複数系統はマルチベンダー CLI（cursor-agent / agy）経由でのみ1 CLI から供給できる。ADR 0009 の Codex→codex 特例は系統照合に吸収され削除。過去 ADR は記録として本文を変更しない（0009 は Status 注記のみ）。
