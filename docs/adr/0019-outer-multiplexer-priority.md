# mux.sh のバックエンド判定は、外側のマルチプレクサを優先する

Status: accepted

`mux.sh detect` は、複数の TUI マルチプレクサが見える環境でどれを選ぶかを判定順で決める。これまでの順は herdr → cmux で、内側（ターミナルの上で動く herdr）が先だった。Rex バックエンドの追加にあわせて **rex → cmux → herdr の順に変え、ターミナルと一体のマルチプレクサ（Rex / cmux）を、その上で動く herdr より優先する。** herdr はターミナルの上で動くマルチプレクサであり、その土台であるターミナル側にペイン操作と状態の取得手段があるなら、そちらを使うのが基本だからである（ユーザー判断）。Rex ではハーネスの状態申告（OSC 7501）がターミナルへ直接届くため、状態の検知も外側のほうが確実になる。

**マルチプレクサを入れ子で使う構成（Rex や cmux のペインの中で herdr を動かし、その herdr のペインに指揮者がいる）は対象外とし、対応する処理も案内も持たない。** この構成で外側を選ぶと、指揮者ペイン ID は herdr 全体を載せている外側のペインになり、委譲先からの push は herdr がその時点でフォーカスしているペインに入る。

## Considered Options

- **内側を優先する（herdr → cmux → rex）** — 却下。入れ子のときに指揮者のいるペインを正しく指せるが、入れ子は想定する使い方ではなく、想定外の構成のために判定順を決めない。
- **入れ子を検出したら detect を失敗させる** — 却下。対象外の構成のための処理を増やさない。
- **外側を優先する（採用）**。

## Consequences

- cmux のペインの中で herdr を使っている環境では、選ばれるバックエンドが herdr から cmux に変わる。
