# iterate-review を移管しレビュアー既定をサブエージェントからハーネスペインへ変更する

Status: accepted

iterate-review（レビュー→修正→再レビューを GREEN まで回す品質ゲート）を claude-skills から本リポジトリへ移管する。移管自体は ADR 0007 で更新した振り分け基準（実行エージェント固有依存の有無）の適用である — iterate-review の実装は gh / git ベースでほぼ中立であり、CC 固有依存はレビュアー既定（Claude サブエージェント）と AskUserQuestion の3箇所だけだった。本 ADR の主眼はあわせて行った**レビュアー解決の再設計**の記録である。

レビュアーの解決順を「① セッションの review 配役 → ② tui-harness のハーネスペイン（既定 codex・`--reviewer` で指定可・ループ中は同一ペインへ追送）→ ③ サブエージェント（著者と別個体）への縮退 → ④ 中止」に変更し、**既定を②のハーネスペインへ昇格**した。旧既定のサブエージェントは実行エージェントと同一モデルであり、著者（修正を行う実行体制も多くは同系統）に対する自己査読に近い構造だった — concertino が implement×review の同一編成を「同一モデルの自己査読」を理由に禁じているのと同じ論理で、レビュアーは異系統ハーネスを既定とする。③は TUI 環境が無い・tui-harness が見つからない・既定 codex が疎通不能の場合の縮退で、同系統査読である旨の明記を義務づける（黙って縮退しない）。`--reviewer` の明示指定が疎通不能の場合は縮退せず中止する（勝手な差し替えをしない）。④で実行エージェント本体の自己レビューを許さないのは、レビューと修正の同一パス化（自己承認）を避けるためである。

契約とペイン文脈の重複は意図的に両方維持する: レビュー契約（却下履歴・保留一覧）はセッションを跨ぐ再開の正本、同一ペインの文脈保持は説明コストの削減であり、役割が異なる。

検証: 2026-08-15 のスモーク2本。CC 指揮者では欠陥入り文書に対し 4 ラウンド（指摘 11→5→3→GREEN）を codex レビュアーペインの追送で完走し、契約運用・スコアボード・後始末（ペインクローズ・一時領域削除）を確認。codex 指揮者では `.agents/skills/` 解決からの一巡を実測。

## Considered Options

- **サブエージェント既定を維持しペインを追加経路に** — 却下。CC では同系統査読のままになり、汎用化の実益がハーネス側にしか出ない。
- **配役必須化（配役が無ければ中止）** — 却下。iterate-review 単体で完結しなくなる。
- **ハーネスペイン既定＋サブエージェント縮退（採用）**。
- **廃止（アーカイブ）** — 却下。反復ループ・レビュー契約・任意対象という固有価値に代替が無い。

## Consequences

- claude-skills の収録は memory-dream のみになる。
- レビューループ語彙（GREEN・レビュー契約・保留）は本リポジトリの CONTEXT.md へ移す。
- AskUserQuestion 3箇所は散文提示へ置換。修正体制の maestro 名指しは同居参照として維持。
- git 履歴は移植しない（過去の変更履歴は claude-skills 側に残る）。
