# concertino `--implement` 奏者の規律（正本）

SKILL.md「ロール固有の規律」のポインタから、編成に implement 奏者がいるときに最初のブリーフを書く前に読まれる。

**パート譜**: 各奏者のブリーフに、排他的な担当ファイル集合（パート譜）を明記する。どのファイルも、それを担当する奏者は常に一人（single-writer の一般形）。複数タスクから触られそうな共有ファイルは、配分の時点で一人のパート譜に寄せる。ブリーフには主文として「書き込みはパート譜に列挙したファイルと成果物置き場（`.concertino/<奏者ラベル>/`）にのみ行う。その外への書き込みが必要になったら、書かずに作業を止めて質問せよ」を明記し、tui-harness「タスクの委譲」の通信規約ブロックにある「書き込みは <成果物置き場> の配下のみ。それ以外のファイルは作成・編集しない。」の行は「書き込みはパート譜に列挙したファイルと <成果物置き場> の配下のみ。それ以外のファイルは作成・編集しない。」に置き換えて渡す（一字一句コピーの規定に対する本スキルの明示的な差し替え。指揮者側の裁定スコープ〔パート譜＋成果物置き場〕と一致させるため）。質問が来たら指揮者が再配分する: 対象ファイルが他奏者のパート譜に無ければその奏者のパート譜を拡張し、有れば当該作業を先行奏者の完了後へ直列化する。配役中、プロジェクトのファイル（成果物置き場 `.concertino/` 配下と `.git/info/exclude` を除く）の内容の変更はすべて奏者に委ねる（指揮者はそれらのファイルには編集ツール〔Claude Code では Write / Edit / NotebookEdit〕もシェル経由の書き込みも使わず、1 行の修正も自分では行わない。指揮者が自分で書くのはブリーフ・差分・バックアップ・承認済みの exclude 追記だけ）。git 環境ではコミット・stash・ブランチ作成をしない（変更は作業ツリーに累積させ、コミットはユーザーの指示があった場合のみ）。非 git 環境では編集タスクの開始前に対象ファイルを成果物置き場（`.concertino/<奏者ラベル>/`）へバックアップし、そのパスを報告する。
