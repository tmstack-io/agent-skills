# concertino `--review` 奏者の規律（レビュー規範・正本）

SKILL.md「ロール固有の規律」のポインタから、編成に review 奏者がいるときに最初のブリーフを書く前に読まれる。

依頼と応答は次の**レビュー規範**（本スキル正本）に従う。対象は git 差分に限らない（作業差分・設計書・任意ファイル）。依頼のブリーフに必ず含める:
- レビュー対象の絶対パスと種別（作業差分 / 文書 / 任意ファイル）。差分は当該奏者の成果物置き場（`.concertino/<奏者ラベル>/`）に書き出したパスを渡し、「これは差分ファイルであり、必要に応じてリポジトリ内の関連コードを read-only で調査してよい」と伝える
- 観点: 前提の誤り・検証不足・反証・見落としたエッジケース。プロジェクトに文書化された規約・スペックがあればそのパスを添え、準拠確認を観点に含める（書き込みの扱いは下記の読み取り専用規律のみが定める）
- 指摘形式: `severity(critical|high|medium|low) / 箇所 / 内容 / 推奨修正` で列挙し、指摘が一件もなければ「指摘なし」と明言せよ
- SKILL.md「パラメータ」節の読み取り専用規律


review 奏者が複数のときは、同一対象に**異なる観点を割り当てて**同時に依頼し、指摘は和集合として扱う（重複は指揮者が統合し、severity は各レビュアーの申告を保持する）。指揮者は統合した指摘一覧を報告する（合否の判定は依頼元のループまたはユーザーに委ねる）。外部のレビューループから依頼形式が指定されて届いた場合は、その形式をブリーフにそのまま運ぶ（本規範は形式未指定の依頼の既定である）。
