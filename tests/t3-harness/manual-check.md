# t3-harness 手動確認手順

T3 Code の委譲ツールはシェルから呼べないため、自動の回帰検証にできない。T3 Code を更新したとき、または `t3-harness/` の「実測」と付した記述を変えるときに、T3 Code 上のエージェントにこの手順を実行させて確かめる。

## 進め方

1. 確認に使う T3 Code のバージョン、指揮者のハーネスとモデル、実行モードを記録する。
2. 下の各項目を上から実行し、項目ごとに「一致」「不一致（観測した内容）」「未実施（理由）」のいずれかを記録する。
3. 不一致が1件でもあれば、`t3-harness/SKILL.md` と `t3-harness/interruptions.md` の該当箇所を観測に合わせて直し、SKILL.md 冒頭の「実測」の定義にあるバージョンを更新する。全項目が一致なら、バージョンだけを更新する。

子に書かせるファイルは、短い絶対パスの一時ディレクトリに置き、確認後に削除する。確認で作られた子スレッドは残るので、不要なら T3 Code の画面で削除する。

直近の実測: T3 Code Nightly 0.1.8-nightly.20261109、指揮者 Claude Code（C10 のみ指揮者 codex）、子は codex と Claude。

## 確認項目

### C1 ツールの存在

- 手順: `t3-harness/SKILL.md`「前置きゲート」の7ツールを名前で探す。
- 期待: 7つとも見つかる。接頭辞は Claude Code で `mcp__t3-code__`、codex で `mcp__t3_code__`。

### C2 能力一覧の形

- 手順: 能力一覧を取得する。
- 期待: 実行中の provider（`inheritedProviderInstanceId`）、実行モード（`runtimeMode`）、provider ごとの `providerInstanceId`・`canRunCrossProviderChildTask`・`constraints`・`omittedModels`、モデルごとの ID とオプション（codex は `reasoningEffort`、Claude は `effort`）が読める。provider の ID は codex が `codex`、Claude が `claudeAgent`。

### C3 同一ターン待ちとエフォート指定

- 手順: codex のモデルへ、エフォートを指定し、`mode: "wait"` と `timeoutMs` を付けて「1行目に DONE、2行目に OK と書け」と委譲する。
- 期待: 同じターンで完了が返り、最終メッセージ（`summary`）に2行が入っている。戻り値からタスク ID と子スレッドの ID・リンクが読める。

### C4 完了通知待ち

- 手順: 同じ内容を待ち方の指定なしで委譲し、子スレッドも状態も読まずにターンを終える。
- 期待: 完了通知がユーザーの発言と同じ形で届き、本文に最終メッセージが入っている。

### C5 長い最終メッセージ

- 手順: 同一ターン待ちで、400行（約29KB）の定型行を最終メッセージに書かせる。
- 期待: 切り詰めなしで返る（子が行を書き崩すことはある）。
- 未検証の追加確認: 完了通知待ちで16KBを超える最終メッセージを書かせ、通知の本文が切り詰められるか、`task_status` で全文を読めるかを記録する。

### C6 子の質問（Claude の子）

- 手順: 完了通知待ちで、Claude のモデルへ「色を質問してから答えを書け」と委譲する。通知を待たずに子の質問の一覧を取り、respond で1回答える。
- 期待: 質問が一覧に出る。respond の戻り値にタスク ID は無い。子は続行し、元のタスク ID のまま完了通知が届く。

### C7 子の質問（codex の子）

- 手順: C6 と同じ内容を codex のモデルへ委譲し、完了通知を待つ。通知の後に子の質問の一覧を取り、respond で1回答える。
- 期待: 子は質問を残したまま完了として戻る。respond すると子が新しいタスクとして動き出し、新しいタスク ID を含む完了通知が届く。
- 未実測の追加確認: 同じ委譲を同一ターン待ちで行い、質問で待ちが切れるか、回答後の結果が完了通知で届くかを記録する。

### C8 承認待ち

- 手順: この項目に限り `runtimeMode: "approval-required"` を付けて、ファイルを1つ書く作業を完了通知待ちで委譲する。
- 期待: 子スレッドに承認要求が出て子が止まる。指揮者には何も通知されず、子の質問の一覧にも出ない。人が子スレッドで承認すると子が完了し、完了通知が届く。

### C9 追送

- 手順: 1回目の委譲で合言葉を伝えて完了させ、完了済みの子スレッドへ「合言葉を答えよ」と送る。
- 期待: 子が合言葉を答える。新しいタスク ID が発行され、完了通知が届く。

### C10 codex が指揮者

- 手順: codex のスレッドで C1・C2 を行い、Claude のモデルへ C3 を行う。
- 期待: C1〜C3 と同じ結果になる。

### C11 中止（未実測）

- 手順: 長い作業を完了通知待ちで委譲し、直後に委譲を中止する。
- 記録する内容: 子が止まるか、完了通知が届くか、戻り値の形。結果に合わせて `t3-harness/SKILL.md`「中止と後始末」の「未実測」を直す。

### C12 同時実行（未検証）

- 手順: 同じターンで3件を完了通知待ちで委譲する。
- 記録する内容: 3件とも動くか、完了通知が委譲ごとに届くかまとめて届くか。
