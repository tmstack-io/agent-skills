# 子が止まったとき・結果が届かないとき

t3-harness の「結果の受け取り」から参照される。該当する節だけに従う。「実測」「未実測」の意味と実測環境は SKILL.md 冒頭の定義に従う。

## 子の質問が残っている

1. 子スレッドを指定して質問の一覧を取り、各質問を読む（承認要求は一覧に出ない。実測）。
2. 答えがブリーフまたはユーザーの指示から導けるならそれを答えにする。導けなければ、質問の内容を散文提示でユーザーに確認して答えを得る。
3. 質問への回答（`t3_pending_request` の respond）で、質問1件につき1回だけ答える。同じ答えを追送で重ねて送らない（2経路で答えると、子が同じ作業を2回実行した。実測）。
4. 答えたらターンを終え、SKILL.md「結果の受け取り」の完了通知待ちで結果を受け取る。同一ターン待ちで始めた委譲も、ここからは完了通知待ちになる（同一ターン待ちが質問で切れた Claude の子に回答すると、元のタスク ID のまま完了通知が届いた。実測）。

回答の戻り値にタスク ID は含まれない（実測）。質問を残して完了で戻った codex の子は、回答すると新しいタスクとして動き出し、新しいタスク ID は完了通知の本文で分かる。Claude の子は質問で止まったまま待ち、回答後は元のタスク ID のまま完了通知が届く（いずれも完了通知待ちでの実測）。届いた完了通知は子スレッドの ID で委譲と対応づける。

完了条件: 残っていた全質問に1回ずつ答え、ターンを終えて完了通知を待っている。

## 同一ターン待ちが承認待ちで戻った

承認に答えられるのは人だけである（正本は SKILL.md「ホスト指示との関係」の承認の裁定）。子スレッドのリンクを示し、子スレッドで承認するようユーザーに依頼してターンを終える。結果は完了通知待ちで受け取る。

完了条件: 子スレッドのリンクを示して承認を依頼し、ターンを終えている。

## 同一ターン待ちが時間切れで戻った

時間切れでも子は動き続け、完了すると元のタスク ID のまま完了通知が届く（実測）。失敗規律が定めた対処を実行する — 完了通知待ちへ切り替えて結果を待つ、または委譲を中止する（再委譲・縮退と定められている場合は、先に委譲を中止してから行う）。同じターンで状態を読み直さない。

完了条件: 失敗規律が定めた対処（完了通知待ちへの切り替え、または中止と、その後の再委譲・縮退）を実行している。

## ユーザーの発言で始まったターンに未回収の委譲がある

完了通知が届かないまま残る、稀な回収漏れへの備えである。未回収の委譲ごとに、識別子と子スレッドのリンクを添えて「結果をまだ受け取っていない」とユーザーへ伝え、ユーザーの依頼への対応を続ける。状態は自動では読まない（実行中の委譲の状態を読むことをホスト指示が禁じている）。ユーザーが回収を指示したときに限り、状態と結果の読み取り（`task_status`）を委譲ごとに1回行い、あわせて子の質問の一覧を取る。質問が残っていれば「子の質問が残っている」に従い、結果があれば SKILL.md「結果の受け取り」の2点の確認へ進む。結果がまだ無ければ、読み直さずに完了通知待ちへ戻る。

完了条件: 未回収の全委譲についてユーザーへ伝えている。回収を指示された委譲は、1回読んで結果を受け取るか、完了通知待ちへ戻っている。

## 子の失敗の原因を調べる

失敗規律が原因の報告を求める場合は、完了で戻った子スレッドをスレッドの読み取り（`t3_thread_read`）で読む。読む量は小さく保ち、足りなければ続きを読む。

完了条件: 失敗規律が求める原因を、子スレッドの記述を根拠に報告している。
