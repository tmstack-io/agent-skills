# t3-harness — T3 Code の委譲ツールで別 provider へ委譲・回収する

> **適用形の確認**: 本書の手順は、利用スキル（本書を Read して同一コンテキストで適用する上位スキル）から適用された場合にだけ実行する。
> ユーザーの名指し起動、または文脈からの自動適用で読み込まれた場合は、本スキルが単発利用の形を持たないこと
> （単発の委譲は T3 Code がエージェントへ与える指示だけで行える）を伝え、何も委譲せずに終える
> （`disable-model-invocation` を解釈しない実行環境での暴発防止）。

T3 Code（Claude Code や codex 等のハーネスを GUI から駆動するホスト）の上で動く実行エージェントが、T3 Code の委譲ツールで別 provider のモデルへ作業を委譲し、結果を回収するまでの共通手順。利用スキルが委譲のたびに「呼び出しパラメータ」を定めて本書を適用する。

- **指揮者**: 本書を適用して委譲する実行エージェント本体。
- **子**: 委譲先で作業するエージェント。子が動く T3 Code のスレッドを**子スレッド**と呼ぶ。
- **ホスト指示**: T3 Code がエージェントへ与える指示（委譲ツールの説明文を含む）。
- **T3 経路**: 本書の手順による委譲。
- **実測**: 本書で「実測」と付した記述は、T3 Code Nightly 0.1.8-nightly.20261109・指揮者 Claude Code での観測を指す（指揮者が違う観測はその場に明記する）。「未実測」「未検証」と付した記述は確かめていない見込みであり、食い違えば実際の挙動に従う。

対話出力（ユーザーへの警告・確認・報告）は対話言語で書く。

## ホスト指示との関係

ホスト指示と本書が食い違う場合は、ホスト指示に従う（ホスト指示は委譲ツールの仕様の一部で、逆らうと委譲が成立しない）。本書は次のホスト指示を前提にする。

- 能力一覧は、スレッドで最初の委譲の前に1回取得する。
- 実行中の委譲の状態を繰り返し問い合わせない（状態の読み取りも sleep も使わない）。
- レビューと再確認は、毎回新しい委譲で行う。
- 指示なしに provider を切り替えない。

本書が持たない仕組みは次の3つ。必要な利用スキルが自分で定める。

- **承認の裁定**: 子の承認要求に答えられるのは人だけである（実測）。書き込み範囲は通信規約で子に指示し、守られたかの事後検査は利用スキルが定める。
- **作業場所の隔離**: 子は指揮者のチェックアウトを共有する。委譲の `isolation`・`runtimeMode`・`interactionMode` は指定しない（実行モードは指揮者から継承される）。
- **モデル系統の判定**: 異系統の組を求める利用スキルが、自分の規定で確定する。

## 前置きゲート

作業開始前に、次の7つの能力に当たるツールがすべて使えることを確かめる。ツールは遅れて読み込まれることがあるため、見当たらないものは、ツール検索できる環境では名前で1回検索してから無いと判定する（Claude Code では ToolSearch）。環境変数（`T3CODE_THREAD_ID` 等）は判定に使わない（文書化された仕様ではなく、ハーネスによって入り方が違う）。

| 能力 | ツール名 |
|---|---|
| 能力一覧の取得 | `orchestrator_capabilities` |
| 委譲 | `delegate_task` |
| 委譲の状態と結果の読み取り | `task_status` |
| 委譲の中止 | `task_cancel` |
| 子の質問の一覧・読み取り・回答 | `t3_pending_request` |
| スレッドの読み取り | `t3_thread_read` |
| 完了済みの子への追送 | `t3_thread_send` |

ツール名の接頭辞はハーネスごとに違う（Claude Code では `mcp__t3-code__`、codex では `mcp__t3_code__`。いずれも実測）。本書が使うツールはこの7つに限る。

1つでも無ければ、無かった能力を添えて「T3 経路は不成立」を利用スキルへ返し、何も委譲しない。7つとも有れば、このスレッドでまだ取得していない場合に限り能力一覧を1回取得する。

完了条件: 7つすべての存在を確認して能力一覧を手元に持っている。または「T3 経路は不成立」を返して終了している。

## 呼び出しパラメータ

利用スキルは、委譲を始める前に次の全項目を定める。

- **委譲先**: `<CLI名>[=<モデル>[@<エフォート>]]` の書式の指定値。省略を許すかどうかも定める（省略された部分の扱いは「委譲先の確定と検証」）。
- **ブリーフ**: 委譲する作業の記述と、その言語。
- **待ち方**: 次のどちらか。
  - **同一ターン待ち** — 結果を同じターンで受け取る。待つ時間（`timeoutMs`）を60分以内で必ず定める（省くと T3 Code の既定の10分で待ちが切れる）。1回で終わる委譲に向く。質問・承認待ち・時間切れで待ちが切れると、続きはターンをまたぐ。
  - **完了通知待ち** — 委譲したらターンを終え、完了通知を待つ。長い作業を任せて対話を続ける委譲に向く。
- **書き込み範囲**: 子が書いてよいパスの集合、または「書き込みなし」。守られたかの事後検査（作業ツリーの差分確認等。git 管理外での方法を含む）もあわせて定める。
- **結果の形式**: 子が最終メッセージに書く内容。結果は最終メッセージで受け取るのを既定とする（子にファイルを書かせなければ、パスの書き写し間違いが起きず、差分が無いことで書き込みなしを検査できる）。ファイルでの受け渡しが要るときだけ成果物置き場を定め、短く区切り記号の少ない絶対パスにする（子が長いパスを書き写し間違えて別ディレクトリへ書いた。実測2回）。
- **識別子**: 委譲ごとに一意な短い名前。子スレッドの題名に使う。
- **失敗規律**: 委譲の起動の失敗（委譲のツールがエラーを返した）・子の失敗・同一ターン待ちの時間切れ・検証の失敗（「結果の受け取り」の検証、または事後検査の不合格）のそれぞれで、中止・再委譲・縮退のどれにするか。
- **並列の条件**: 複数の委譲を同時に動かす場合の条件（編集を伴う委譲はファイル領域が重ならないものに限る等）。同時実行数の上限は未検証。
- **追送の可否**: 完了済みの子へ続きを依頼してよい場面（「追送」節）。

完了条件: 委譲を始める前に、上の全項目が確定している。

## 委譲先の確定と検証

利用スキルから受け取った委譲先の指定値を能力一覧と照合して、次の順に確定する。

1. **provider**: CLI名を能力一覧の provider（`providerInstanceId`）へ対応づける。対応は `codex` → `codex`、`claude` → `claudeAgent` の2件（実測）。それ以外の CLI名は「T3 経路では未実測のため非対応」と示して中止する（対応を増やすには、実測してからこの対応に加える）。CLI名が未指定なら、2件のうち実行中の provider と異なり、かつ手順3を満たすものを候補とする。候補が2件なら散文提示して選んでもらい、1件ならそれを採用してユーザーへ伝え、0件なら能力一覧が示す制約を理由として示して中止する。
2. **実行中と同じ provider か**: provider が能力一覧の実行中の provider（`inheritedProviderInstanceId`）と同じなら、本書の手順を適用せず、「委譲先は実行中と同じ provider で、手段の選択はホスト指示による」と利用スキルへ返す（本書の対象は別 provider への委譲）。
3. **委譲できるか**: provider が能力一覧にあり、別 provider への委譲が可能（`canRunCrossProviderChildTask` が真）であること。満たさなければ、一覧が示す制約（`constraints`）を理由として示して中止する。
4. **モデル**: 指定値を当該 provider のモデル ID と照合する。一覧が省略されている場合（`omittedModels` が1以上）で見つからなければ、指定値で検索して引き直す（能力一覧の `search`）。完全一致なら採用し、大文字小文字・区切り記号・部分一致のゆれで候補が1件なら一覧上の ID へ是正して採用する。候補が0件または2件以上なら散文提示で再指定を求める。未指定なら一覧を散文提示して選んでもらう。
5. **エフォート**: `@<エフォート>` があれば、当該モデルのオプション（codex は `reasoningEffort`、Claude は `effort`。実測）の許容値と照合し、外れていれば許容値を示して散文提示で再指定を求める。省略時は指定しない（provider の既定に従う）。
6. **実行モード**: 能力一覧の実行モード（`runtimeMode`）が `full-access` 以外なら、委譲の前に「子が承認待ちで止まることがあり、その場合は子スレッドで人が承認する必要がある」とユーザーへ警告する。完了通知待ちでは、承認待ちは指揮者に通知されず、人が承認するまで完了通知も届かない（実測）。同一ターン待ちでは、承認待ちで待ちが切れる（ホスト指示の記述による。未実測）。

上のフィールド名は実測時点のもの。違っていれば、応答の実際の形から同じ意味の値を読む。

完了条件: provider・モデル ID・エフォート（指定時）が能力一覧と照合済みで、実行モードの確認（該当時は警告）が済んでいる。または中止・返却している。

## 委譲

1. **ブリーフを組み立てる**: 子に渡るのは委譲の `task` の文字列だけで、指揮者の会話は渡らない。ブリーフは全文を `task` に書き（ファイルで渡さない）、委譲する作業の記述に続けて、末尾に次のブロックを**一字一句そのままコピー**し、`<>` 内を実値に置換する。書き込み範囲が「書き込みなし」の場合は、1行目を「- ファイルを作成・編集しない。」に差し替える。

   ```
   BEGIN-通信規約
   - 書き込みは <書き込み範囲> のみ。それ以外のファイルは作成・編集しない。
   - git のコミット・stash・ブランチ作成はしない。変更は作業ツリーに残す。
   - 不明点で作業を続けられないときは、推測で進めず、作業を止めて質問する。
   - 最終メッセージだけが依頼元に渡る。1行目に DONE か FAILED の1語を書き、2行目から <結果の形式> を書く。
   END-通信規約
   ```

2. **委譲する**: `task` にブリーフ、委譲先に確定済みの provider・モデル ID・エフォート（指定時のみ、オプションとして）、題名に識別子を渡す。同一ターン待ちでは `mode: "wait"` と `timeoutMs` を渡し、完了通知待ちでは待ち方を指定しない（既定の非同期）。並列の条件を満たす委譲は、同じターンで複数起動してよい。
3. **記録する**: 委譲ごとに、識別子・タスク ID・子スレッドの ID とリンクを控える。以後の追跡は子スレッドの ID で行う（質問への回答でタスク ID が変わることがある。実測）。

完了条件: 起動した全委譲について、識別子・タスク ID・子スレッドの ID とリンクを控えている。起動に失敗した委譲は、失敗規律に従って終えている。

## 結果の受け取り

待ち方ごとに次のとおり受け取る。

- **同一ターン待ち**: 委譲の戻り値が完了を示せば、その最終メッセージ（`summary`）が結果である（約29KBの最終メッセージが切り詰めなしで返った。実測）。完了以外で戻った場合は、戻り値が示す理由（質問・承認待ち・時間切れ）で `interruptions.md` の節を選ぶ。理由を示す値の形は未実測である。戻り値から読み分けられなければ、子スレッドを指定して子の質問の一覧を取り、1件以上あれば質問として扱い、0件なら承認待ちの可能性があるものとして「同一ターン待ちが承認待ちで戻った」節に従う。
- **完了通知待ち**: 委譲したらターンを終える。完了通知はユーザーの発言と同じ形で届き、委譲ごととは限らず、まとめて届くことがある。散文提示の回答待ちの間に届いても、回答として扱わない。通知が届くまで、当該委譲の状態も子スレッドも読まない（先に読むと受け取り済みの扱いになり、通知が届かなくなる。実測2件からの推測）。通知の本文が切り詰められていれば、状態と結果の読み取り（`task_status`）で全文を読む（全文が読めるかは未検証）。

完了で戻った委譲は、結果を使う前に次の2点を確かめる。

1. **保留の質問**: 子スレッドを指定して子の質問の一覧を取る。codex の子は、質問を出したままターンを終えて完了として戻る（実測）。1件でも残っていれば未完了として扱う。
2. **1行目の検証**: 最終メッセージの1行目が `DONE` なら2行目以降を結果として利用スキルへ渡す。`FAILED` なら子の失敗、どちらでもなければ検証の失敗として、利用スキルの失敗規律に従う。

次のいずれかが起きたら、対処の前に本スキル同フォルダの `interruptions.md` を全文 Read し、該当する節に従う: 子の質問が残っている、同一ターン待ちが質問・承認待ち・時間切れで戻った、ユーザーの発言で始まったターンに未回収の委譲がある、子の失敗または検証の失敗で失敗規律が原因の報告を求めている。

完了条件: 起動した全委譲について、保留の質問が0件で、最終メッセージの1行目を検証し終えている。または失敗規律に従って終えている。

## 追送

完了済みの子へ続きの依頼を送ると、前の文脈を保った新しいタスクとして始まる（実測）。使うのは利用スキルが明示した場面（実装の差し戻し等）に限る。本文の末尾に通信規約ブロックを付け、結果は完了通知待ちで受け取る。

完了条件: 追送した全件の結果を「結果の受け取り」の完了条件まで受け取っている。

## 中止と後始末

不要になった委譲と、置き換える委譲は、委譲の中止（`task_cancel`）で止める（中止の挙動は未実測）。子スレッドは削除せず（削除はユーザーの操作に属する）、利用スキルの最終報告に、起動した全委譲の識別子と子スレッドのリンクを列挙する。リンクは受け取った文字列のまま書く。

完了条件: 動かし続ける理由の無い委譲がすべて止まっており、起動した全委譲の子スレッドのリンクを報告している。

## git への態度

本書の手順は git の履歴に触れない（コミット・stash・ブランチ作成をしない）。子にも通信規約で同じことを指示する。git 管理外でも手順は変わらない。
