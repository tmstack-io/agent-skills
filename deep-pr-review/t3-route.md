# deep-pr-review T3 経路

フェーズ0 手順0で TUI 経路が成立しなかった場合にのみ読む、T3 経路（T3 Code の委譲ツールで外部レビュアーを起用する経路）固有の規定の正本。SKILL.md の「散文提示」等の定義を引き継いだ同一コンテキストで適用する。T3 経路が置き換えるのは外部レビュアーの起用（フェーズ0 手順4・フェーズ1-B・後始末のペイン関連）だけで、それ以外のフェーズは SKILL.md のとおりに進める。

共通手順（委譲ツールの存在確認・委譲先の検証・委譲・結果の受け取り・質問と承認待ちへの対処・中止）の正本は t3-harness であり、本書は t3-harness の利用スキルとして呼び出しパラメータを定める。

## 経路の成立判定

1. `t3-harness/SKILL.md` を SKILL.md フェーズ0 手順1と同じ探索順で解決して Read する。見つからなければ不成立とする。
2. t3-harness の「前置きゲート」を適用する。「T3 経路は不成立」が返れば不成立とする。

不成立の場合は**レビューを開始せずに中止**し、次の2つを案内する: 検証済み TUI マルチプレクサ内での再実行。T3 Code 上で実行している場合は t3-harness の導入（例: `npx skills add tmstack-io/agent-skills --skill t3-harness`）。

完了条件: T3 経路の成立を確認して能力一覧を手元に持っている。または中止して2つの案内を出している。

## レビュアー確定（フェーズ0 手順4の代わり）

1. 実行中のモデル系統を、SKILL.md フェーズ0 手順4の1項目めと同じ規則で確定する。
2. `--cli` の1出現をレビュアー1体として、t3-harness の「委譲先の確定と検証」を適用する。同一 CLI の重複指定は中止する。`--cli` が無ければ、同節の CLI名未指定の扱いに従って1体を確定する。モデル未指定のレビュアーには、同節のモデル一覧の散文提示で、実行中と異系統のモデルを優先候補として示す。
3. t3-harness の返事ごとに次のとおり扱う。
   - **中止**（非対応の CLI名・委譲できない provider 等）: 明示指定されたレビュアーなら、t3-harness が示した理由を提示してレビューを中止する。`--cli` が無く候補が0件で中止になった場合は、手順5のサブエージェント代替に進む。
   - **「委譲先は実行中と同じ provider」**: 別 provider のレビュアーを指定し直すか、手順5のサブエージェント代替で続行するかを散文提示で確認する（推奨は指定し直し。理由: 外部レビューの価値は別系統の視点にあるため）。
4. 確定したモデル ID を tui-harness の `catalog.sh family <CLI名> <モデルID>` へ渡して委譲先のモデル系統を得て、実行中と比較する。同系統になった場合の扱い（再指定の散文提示・続行時の `外部レビュー:` 行への明記）は SKILL.md フェーズ0 手順4の4項目めと同じ。
5. **サブエージェント代替**: 起用できるレビュアーが1体も無い場合は、SKILL.md フェーズ0 手順4の5項目めと同じ規定（独立コンテキストの読み取り専用サブエージェント1体による代替と明記、起動できなければ skip と明記）に従う。

完了条件: 全レビュアーの provider・モデル ID・エフォート（指定時）・モデル系統が確定している。またはサブエージェント代替・skip・中止のいずれかが確定している。

## 委譲と回収（フェーズ1-B の代わり）

SKILL.md フェーズ0 手順5で worktree フォールバック（`gh pr checkout`）を使った場合は、TUI 経路と同じくフェーズ1-B を skip して `外部レビュー:` 行に明記する。サブエージェント代替が確定している場合は SKILL.md フェーズ1-B の代替の規定に従い、本節は適用しない。

**呼び出しパラメータ**（t3-harness の全項目）:

- **委譲先**: 「レビュアー確定」で確定した値（レビュアーごと）。
- **ブリーフ**: SKILL.md フェーズ1-B の「ペインを使わない委譲のブリーフ」（子の作業ディレクトリは指揮者のチェックアウトであり、PR head worktree ではないため）。言語はフェーズ0で確定した成果物言語とする。
- **待ち方**: 同一ターン待ち。待つ時間は60分とする。
- **書き込み範囲**: 書き込みなし。事後検査は本節の手順4。
- **結果の形式**: SKILL.md フェーズ1-A と同一の返却フォーマット（`観点:` は `外部`。指摘が無ければ「指摘なし」）。
- **識別子**: `dpr-<CLI名>`。
- **失敗規律**: 委譲の起動の失敗・子の失敗・検証の失敗は、SKILL.md の再委譲の共通規律に従い、同一内容の新しい委譲を1回だけ行う。それでも結果が得られなければ当該レビュアーを skip 扱いとする。同一ターン待ちの時間切れは、当該委譲を中止して skip 扱いとする。skip の理由は `外部レビュー:` 行に明記し、他のレビュアーとフェーズ1-A は続行する。
- **並列の条件**: 全レビュアーが書き込みなしのため、全員を同時に委譲してよい。
- **追送の可否**: 不可（やり直しは新しい委譲で行う）。

**手順**:

1. **事前の記録**: 委譲の前に、セッションの作業ツリーと `$WT_DIR` のそれぞれで `git status --porcelain` を実行し、出力を控える。
2. **委譲**: フェーズ1-A のサブエージェントを起動し、続けて t3-harness の「委譲」で全レビュアーを委譲する（複数のツールを同時に呼べる環境では、フェーズ1-A の起動と同じ発話で委譲する）。
3. **回収**: t3-harness の「結果の受け取り」に従い、最終メッセージの2行目以降を `findings_<CLI名>`（構造は SKILL.md フェーズ1-B 手順3と同じ）として保持する。待ちが質問・承認待ちで切れた場合は t3-harness の規定で対処し、完了通知で結果を受け取ってからフェーズ2へ進む（ブリーフの自律完走指示から導ける質問には「前提を明記した上で完走せよ」と答える）。届いた完了通知は、散文提示への回答として扱わない。
4. **汚染検査**: 全レビュアーの回収（または skip 確定）後、手順1と同じ2箇所で `git status --porcelain` を実行し、手順1の出力と比べる。増えた差分があれば「外部レビュアーによる規律外の書き込みの疑い」として、該当パスを最終出力の `注記:` に警告として明記する（差分には触れない。T3 経路では子の書き込みを事前に止められず、セッションの作業ツリーへの書き込みは実害になりうるため、必ず知らせる）。

`外部レビュー:` 行の実施の但し書きには「T3 経路」を併記する。

完了条件: 全レビュアーについて `findings_<CLI名>` を保持しているか skip が確定しており、汚染検査の結果（差分なし、または `注記:` への警告）が確定している。

## 後始末（SKILL.md「後始末」のペイン関連の代わり）

T3 経路にペインは無いため、SKILL.md「後始末」の手順1と、手順3のペインの検証は行わない。代わりに次を行い、手順2と手順3の残りは SKILL.md のとおり実行する。

1. 結果を受け取っていない委譲が残っていれば、t3-harness の「中止と後始末」で止める（途中中止の場合を含む）。委譲を放棄した場合は、その旨を報告に含める。
2. 起動した全委譲の識別子と子スレッドのリンクを、統合レビューの出力後の対話出力（SKILL.md フェーズ5 手順4の案内）に列挙する。統合レビューの本文には入れない。

完了条件: 動いている委譲が残っておらず、起動した全委譲の子スレッドのリンクを報告している。
