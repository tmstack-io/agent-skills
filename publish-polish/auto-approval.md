# publish-polish 自動承認（`--auto`）の規定（正本）

publish-polish の承認方式のうち自動承認の正本。引数に `--auto` が含まれる起動では、走査を始める前にこのファイルを読了し、以下に従う。SKILL.md の各工程にある「自動承認では〜」の記述は、この規定を当該工程の場面に当てはめた挙動であり、採用値の意味と肩代わりの範囲の正本はこのファイルにある。

## 引数の解釈

- **`--auto [推奨|全件]`**: [4] の承認範囲を、ユーザーの返信の代わりに指定値で確定し、ターンを終えずに [5] へ進む。値を省略した `--auto` は `推奨` とみなす。値の意味は次のとおり:
  - `推奨`: [4] のレポート末尾で自分が示した推奨案（`全件` / 番号指定 / `見送り` のいずれか）をそのまま採用する
  - `全件`: 提案の全件（対話承認の `全件` と同じ範囲）
  - いずれの値でも、要対応（漏えい）は承認範囲に入らない

`--auto` の値が `推奨` / `全件` 以外の場合は、走査を始めず該当箇所と正しい形（上記の書式）を示して中止する。

## 肩代わりする範囲

- **[1] 公開の姿の確認**: 3問を確認しない。本スキルを Read して適用する呼び出し側が①〜③を宣言して渡した場合はその宣言を確定値とし（「呼び出し側の宣言により確定」と書く）、宣言が無ければ「ユーザーが判断を委ねた場合」と同じ推定で確定する。推定した場合はその旨を宣言とレポートの「公開の姿」に書く（判定の前提が推定であることを後から検算できるようにする）。
- **[2] 分割実行の提案**: 提案せず、読み切れる範囲を今回の対象として分割実行の1回目とし、未走査の残りを明示する。
- **[4] 承認範囲**: 上記の採用値で確定する。

## 肩代わりしない範囲

- **要対応（漏えい）の対処方針**: 削除 / 一般化 / 公開可の確認済みは実体を変える判断であり、自動承認では判断しない。要対応はすべて「未対処（自動承認では判断しない）」として適用せず報告に残し、対処にはユーザーの判断が要る旨を報告に書く。
- **対象パスの確認**: 引数が無い起動は自動承認でも従来どおり対象をユーザーに確認して止まる。
- **git 管理外の対象**: [5] の 3 で取る複製が戻す手段になるため、git 管理外でも適用する。複製の保存先パスを報告に必ず載せる。

## 出力の義務

自動承認でも、開始時の承認方式の宣言、[1] の①〜③の宣言、[2] の対象一覧、[4] のレポート全文と確定した承認範囲の一行、[5] の報告は、対話承認と同じく本文へ出力する（提示を省いて承認だけを進めない）。`publish-polish-findings.json` の保存も同様に行う。

## 想定する使い方

他スキルやサブエージェントが本スキルの規定を Read して同一コンテキストで適用する場面で、回答を返すユーザーがいない場合に用いる。呼び出し側は、①〜③を宣言して渡し（無ければ推定になる）、要対応の未対処が報告に残ることを前提に、自身の承認ゲートで人の確認を取る。現行例: pr-comment 同梱の公開整形契約（投稿文面を一時ファイルに書き出し、`--auto 全件 --style` で第1段を実行する）。
